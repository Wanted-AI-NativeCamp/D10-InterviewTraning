# 기존 프로토타입 → PRD v2.1 전환 계획

## 1. 현재 프로토타입(사용자 설명 기준)

새 면접 시작 / Markdown 파일로 이어하기 → 직군·회사·경험 입력 → 5질문 +
질문당 꼬리질문 최대 1개 → 위원 4명 평가 → 재도전 → 리포트 확인 → **면접
완료 후에만 Markdown 저장**.

> 실제 코드·저장 구조는 아직 확인하지 않았다. 아래는 구현 지시 전 점검용
> 계획이다.

## 3. 단계별 적용

### M1. 데이터 분리

Project, ExperienceCard, ExperienceVersion, InterviewAnswer, Evaluation,
Quest 엔터티를 독립화. 기존 경험 입력은 임시 카드로 전환할 수 있도록
설계.

### M2. 경험 관리 및 독립 내보내기

프로젝트·카드 CRUD, 경험만 Markdown 다운로드. **면접 기록이 없어도
동작하는지 우선 QA**.

### M3. 면접 UI 연동

질문별 추천/2개 비교, 참고 여부, 사이드 패널 수정, 답변 draft 유지, 제출
시 버전 고정.

### M4. 평가·퀘스트

AI 평가 결과 저장, 경험 강화/전달 강화 매핑, 과거 평가 불변성 검증.

### M5. 통합 내보내기·호환

경험+면접 통합 Markdown, 진행 중 세션, 기존 면접만 내보내기. 기존
Markdown 이어하기의 파싱 가능 여부 확인.

### M6. 전략 확인

회사별 준비 현황, 일정, 퀘스트 조회.

## 4. 기존 Markdown 기록 처리

-   구형 파일 샘플과 현재 파서 확인 전까지 자동 마이그레이션 보장 금지.
-   구형 파일은 원본 백업.
-   import 가능하면 `schema_version=legacy`로 읽고 누락된 경험 ID/버전은
    안전하게 생성·표시.
-   import 불가능하면 구형 이어하기 기능을 임시 유지하고 새 저장 방식과
    차이를 안내.
-   새 export가 기존 import와 호환된다고 가정하지 말 것.

## 5. 회귀 테스트

1.  기존 5문항 면접 정상 진행.
2.  꼬리질문 최대 1개.
3.  면접 결과·재도전 접근 가능.
4.  **경험만 작성 → Markdown 다운로드**.
5.  경험 2개 작성 → 질문별 비교·선택.
6.  면접 중 카드 수정 → 답변 유지.
7.  카드 v2 수정 → v1 기반 평가 불변.
8.  진행 중 면접 → 통합 Markdown 다운로드.
9.  AI 평가 실패 → 답변 유실 없음.
10. 구형 Markdown 이어하기 동작/제한 명시.

## 6. 팀 결정 필요

-   현재 저장소 구조 및 저장 방식
-   4명 평가위원 유지 여부
-   구형 Markdown import 범위
-   진행 중 미제출 초안 export 기본 정책
-   회사·개인 경험 데이터 보존/삭제 정책

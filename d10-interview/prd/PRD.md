## 0. 1차·2차 MVP 구분과 확정 정책 (v2.3)

이 장은 v2.2 이후 확정된 정책이다. 본문과 다르면 이 장을 우선한다.

### 0.1 개발 단계

| 단계 | 범위 | 상태 |
|---|---|---|
| **1차 MVP — AI 면접 코칭** | 면접 정보 설정 · 공통/분야별 5문항 면접 · AI 면접관 반응과 꼬리질문 · AI 평가(위원별 · 답변별) · 답변 개선 코칭 · 질문별 재도전과 평가 비교 · 회사·직군·회차별 면접 기록 · Markdown v2 저장과 v1·v2 복원 | 개발 대상 |
| **2차 MVP — 경험 정리 · 취업 전략 관리** | 프로젝트·경험 카드 관리 · AI 경험 카드 초안 · 면접 중 경험 카드 추천·비교·선택 · 경험 강화 퀘스트 · 회사별 취업 전략·우선순위(지망 태그) · 지원 현황·일정 · 경험·면접·취업 데이터 통합 · 선택 저장 | 향후 범위 (삭제 아님) |

- 본문에서 2차 범위인 장·항목에는 **[2차 MVP]** 를 표시한다. 표시가 없는 면접 기능은 1차 범위다.
- 1차는 기존 프로토타입의 면접 엔진(질문 출제 · 면접 진행 · 평가 · 재도전)을 최대한 유지하고, 2차에서 면접 기능을 다시 고치지 않도록 데이터 식별자 · 회차 기록 · 저장 구조만 부분 개선한다 (C안).
- 문서의 정책은 **목표 정책**이다. 현재 코드와의 차이는 `MIGRATION.md` 에서 관리하며, 문서에 적었다는 이유로 구현 완료로 보지 않는다.

### 0.2 면접 진행 (1차 확정)

- 기존 '빠른 피드백' 면접 방식은 1차 목표 구조에서 제거하고, **하나의 일관된 면접관 페르소나**로 진행한다. 직군마다 대표 면접관 1명을 자동 배정하고 사용자가 고르지 않는다 (디자인: 디자인 팀장). 면접관은 면접 진행 역할이고, 평가위원 4명은 면접이 끝난 뒤 평가하는 별도 역할이다.
- 본 질문(기본 질문)당 **선택적 꼬리질문 최대 1개**. 한도는 코드가 보장한다.
- 꼬리질문은 **실무 근거 검증**(답변의 근거 · 구체성 확인)을 기본으로 하고, 필요할 때 **경험 탐색**(답변에 드러나지 않은 경험 발굴)에 쓴다.
- 면접 진행 중에는 답변 개선 코칭이나 평가를 제공하지 않는다. 평가 · 코칭 · 재도전은 **면접 완료 후** 제공한다.
- 경험 카드나 사전 경험 등록 없이 면접을 시작할 수 있다. 기존 자유 서술형 '내 경험' 입력은 **선택 입력**으로 유지한다 (글자 수 필수 조건 없음). 면접관 질문의 개인화에만 참고하고, 실제 제출 답변에 없는 사전 경험은 평가 근거로 쓰지 않는다. 경험 카드와는 별개 기능이다.
- **회사 등록 · 선택은 필수가 아니다.** 직군(직무)과 분야만 골라 면접을 시작할 수 있다. 회사를 지정하지 않은 면접 기록은 화면에서 **'기타'** 그룹으로 분류하고, '기타' 그룹에서도 회차 · 질문 · 답변 · 평가 · 재도전 기록을 유지한다 (0.6).

### 0.3 평가 (1차 확정)

- 평가 대상은 사용자가 **실제로 제출한 면접 답변**이다. 사전에 등록 · 입력한 경험 내용 자체를 평가 근거로 쓰지 않는다.
- 기존 평가 체계(평가위원 4명의 위원별 평가 · 답변별 기준 점수 · 위원 평균 의견)를 유지한다.
- 평가 결과는 당시 질문 · 답변과 연결해 보존하며 이후 변경으로 다시 계산하지 않는다.
- AI 평가 응답은 저장 전에 검증한다: 응답 구조, 평가위원 4명, 평가 항목, 점수 타입(정수), 질문 번호 · ID.
- 검증에 실패하면 **자동으로 1회 다시 요청**하고, 그래도 실패하면 사용자에게 평가 오류를 안내한다. 검증에 실패한 결과는 정상 평가로 저장하지 않는다.
- 누락된 평가위원 점수를 0점으로 채우지 않으며, 질문이 맞지 않는 평가를 다른 질문에 연결하지 않는다.
- 검증을 통과한 응답에서 범위(위원 0~10 · 기준 0~5)를 벗어난 정수 점수는 경계값으로 보정하고, 합계 · 평균은 보정한 점수로 코드가 계산한다. (`d10-interview/CLAUDE.md` 의 '점수는 범위 밖이면 잘라 쓴다' 와 같다.)
- 자동 재시도는 오류 복구 수단이다. 검증 실패가 반복되면 프롬프트와 평가 기준을 점검한다. 평가 항목별 점수 범위와 계산 방식은 기존 명세를 따르며 (`technical/AI_RULES.md`), 사용자 승인 없이 바꾸지 않는다.

### 0.4 재도전 (1차 확정)

- 재도전은 새 면접 회차가 아니라 **기존 회차에 속한 답변 개선 이력**이다. 회차 번호를 늘리지 않는다.
- **재도전 횟수 제한은 없다.** 횟수 초과 차단 · 남은 횟수 표시 · 제한용 카운터를 두지 않는다.
- 원본 답변과 기존 재도전 기록을 유지하고, 새 답변과 평가 결과를 별도 이력으로 누적한다.
- 재도전 기록은 `round_id` · `question_id` 에 연결하고, 기록마다 고유 ID(`attempt_id`)를 둔다. 재도전 순서는 저장된 기록으로 계산한다.
- 새 회차를 진행하지 않아도 Markdown 복원 후 기존 회차에서 바로 재도전할 수 있다 (6.7).

### 0.5 저장 · 복원 (1차 확정)

- 전체 기록(여러 회사 · 직군 · 회차)을 **하나의 Markdown v2 파일**로 저장한다. 사람이 읽는 본문과 복원용 데이터(`interview-data` 태그 · `version: 2`)를 함께 담는다.
- 기존 Markdown v1 파일을 계속 읽을 수 있다. 지원하지 않는 버전은 안내하고 안전하게 거부한다.
- 기존 파일을 자동으로 덮어쓰지 않는다. 원본 답변 · 재도전 기록 · 과거 평가는 당시 상태로 보존한다.
- 과거 Markdown 파일에 **현재 질문 은행에 없는 질문**이 있어도 당시 질문 원문 · 최초 답변 · 기존 평가 · 재도전 이력 · 기록의 연결 관계를 보존하고, 그 질문에도 재도전할 수 있다 (기존 질문 원문 기준, 과거 평가는 다시 계산하지 않음). 이런 질문을 다른 질문에 임의로 연결하지 않는다. 질문 ID 매핑에 실패했을 때의 내부 식별 · 변환 방식은 **미확정**(P1 에서 결정)이다.
- 선택 저장은 2차 방향만 확정했다. 저장 단위 · 화면 · 선택 · 제외 방식 · 확인 절차 · 삭제와의 관계는 **미확정**이다.

### 0.6 데이터 식별 (1차 확정)

| 대상 | 규칙 |
|---|---|
| 회사 | `company_id`(고유 ID, 별도 생성) · `company_name`(표시 이름) · `company_key`(비교용: 앞뒤 공백만 제거, 중간 공백 · 대소문자는 그대로). `company_key` 가 정확히 같으면 같은 회사. 회사명 변경 UI는 2차 |
| 회사 미지정 | 회사를 지정하지 않은 면접은 화면에서 **'기타'** 그룹으로 보여 준다. 화면의 '기타'와 실제 회사명이 '기타'인 회사를 구분하며, 회사 미지정 상태를 실제 회사 데이터로 취급하지 않는다. 내부 식별 방식과, 미지정 기록을 나중에 특정 회사로 옮기거나 연결하는 기능은 **미확정**이다 |
| 회차 | `round_id`(고유 ID) · `round_number`(표시 번호). 회차 번호는 **회사(또는 '기타' 그룹) + 직군(직무)** 기준으로 누적하고, 공통 · 분야별 면접이 같은 번호 체계를 쓰며, 재도전으로 늘지 않는다. v1 복원 시 같은 기록에 같은 ID를 매핑해 반복 업로드로 중복 · 덮어쓰기가 생기지 않게 한다 |
| 질문 | `Q0001` 형식의 영구 ID. 바꾸거나 다시 쓰지 않고, 문구 · 분류가 바뀌어도 유지. 새 질문은 새 ID. 과거 기록에는 당시 질문 문구를 함께 보존. 현재 질문 은행에 없는 과거 질문은 0.5 를 따른다 |

회차 번호 예시:

| 그룹 | 직군(직무) | 회차 | 면접 유형 |
|---|---|---|---|
| A회사 | 디자인 | 1회차 | 공통 면접 |
| A회사 | 디자인 | 2회차 | 분야별 면접 |
| A회사 | 디자인 | 3회차 | 공통 면접 |
| A회사 | 개발 | 1회차 | 분야별 면접 |
| 기타 (회사 미지정) | 디자인 | 1회차 | 공통 면접 |

세부 구조는 `technical/DATA_MODEL.md` 를 따른다.

### 0.7 용어

| 용어 | 뜻 |
|---|---|
| 직군 (직무) | 사용자가 선택한 지원 직무 (예: 디자인, 개발). 문서에서 '직군'과 '직무'는 같은 뜻이다 |
| 분야 | 질문의 산업 분야 (예: 공통, 헬스케어, 핀테크 · 금융). 분야별 면접에서 고른다 |
| 면접 유형 | 질문 구성 유형: 공통 면접(공통 5문항) / 분야별 면접(공통 2 + 분야 3). 회차를 나누는 기준이 아니다 |
| 회사 그룹 | 같은 회사(`company_key`)의 기록 묶음. 회사 미지정 기록은 '기타' 그룹 |
| 회차 | 회사(또는 '기타') + 직군(직무) 안에서 새 면접을 시작할 때마다 하나씩 늘어나는 면접 단위 |
| 재도전 | 기존 회차의 질문에 다시 답한 개선 이력 (회차가 아님) |

## 1. 서비스 개요

### 1.1 서비스명

**역전 취업 코칭**

### 1.2 서비스 정의

별도의 경험 등록 없이 빠르게 면접을 시작하고, AI 평가를 바탕으로 경험과 면접 전략·일정을 체계적으로 관리하며 취업 전략을 개선하는 AI 취업 코칭 서비스.

### 1.3 서비스 목적

취업 준비자가 별도의 경험 등록 없이 빠르게 면접을 시작하고, AI 평가를 통해 자신의 강점과 보완할 점을 발견할 수 있도록 돕는다.

면접 답변에서 발견한 경험을 체계적으로 기록·관리하고, 지원 회사와 면접 질문에 적합한 경험을 전략적으로 활용할 수 있도록 지원한다.

면접 평가와 경험 관리, 준비 일정 및 퀘스트를 연결하여 지속적으로 답변을 개선하는 반복 학습 경험을 제공한다.

### 1.4 이번 MVP의 범위

서비스명은 '역전 취업 코칭'이지만, MVP는 두 단계로 나누어 개발한다 (0.1).

**1차 MVP — AI 면접 코칭**

- 공통 면접 및 분야별 면접
- AI 면접 평가 및 회차별 기록 관리
- 면접 재도전 및 개선 점수 확인
- Markdown 데이터 저장(v2 통합) 및 복원(v1 · v2)

**2차 MVP — 경험 정리 · 취업 전략 관리** (향후 범위)

- 프로젝트 및 경험 카드 관리
- AI 경험 카드 초안 생성
- 경험 강화·전달 강화 퀘스트 (1차 퀘스트 전환 범위는 미확정, 5.4)
- 회사·직군별 지원 정보 및 일정 관리

이력서 자동 작성, 채용공고 추천, 포트폴리오 제작, 암기용 답변 관리 등은 현재 개발 범위에 포함하지 않는다.

## 2. 문제 정의

### 2.1 핵심 문제

취업 준비자는 다양한 프로젝트와 실무 경험을 보유하고 있어도, 지원 회사와 면접 질문에 적합한 경험을 선택하고 체계적으로 관리하는 데 어려움을 겪을 수 있다.

또한 자신의 경험을 충분히 이해하고 있더라도 면접 답변에서 구체적인 행동과 판단 근거를 효과적으로 전달하지 못할 수 있으며, 평가 이후 어떤 경험을 보완하고 어떻게 답변을 개선해야 하는지 판단하기 어려울 수 있다.

### 2.2 문제 가설

**H1. 경험 선택의 어려움**

사용자는 여러 경험 중 면접 질문에 가장 적합한 경험을 선택하는 데 어려움을 겪는다.

**H2. 경험 기록과 답변 전달의 차이**

사용자는 실제 경험에 대한 정보가 부족한 것인지, 알고 있는 내용을 답변에서 충분히 전달하지 못한 것인지 구분하기 어렵다.

**H3. 평가 이후 개선 행동의 부재**

면접 평가를 받더라도 구체적으로 어떤 경험을 보완하고 어떤 답변을 연습해야 하는지 파악하기 어렵다.

**H4. 면접 준비 정보의 분산**

지원 회사별 경험, 답변, 평가, 준비 일정이 분산되어 면접 준비 현황을 종합적으로 확인하기 어렵다.

위 내용은 검증이 필요한 문제 가설이며, 실제 사용자 조사 결과로 확정된 사실은 아니다.

## 3. 타깃 사용자

### 3.1 핵심 사용자

**프로젝트 또는 실무 경험을 보유한 취업 준비자**

- 신입 및 중고신입 지원자
- 프로젝트 경험이 있는 직무 전환 준비자
- 지원 직무에 맞춰 기존 경험을 재구성해야 하는 사용자
- 면접을 앞두고 자신의 경험과 답변을 점검하려는 사용자

### 3.2 주요 사용자 특성

- 활용할 경험은 있지만 질문에 맞는 사례 선택이 어렵다.
- 자신의 역할과 행동을 구체적으로 설명하는 데 어려움을 느낀다.
- 동일한 경험을 여러 역량과 질문에 활용하고 싶어 한다.
- 면접 연습 결과를 다음 준비 행동으로 연결하고 싶어 한다.

### 3.3 후순위 사용자

- 활용할 프로젝트나 실무 경험이 거의 없는 사용자
- 아직 희망 직무를 탐색하는 단계의 사용자
- 채용공고 탐색이나 이력서 제작만을 목적으로 하는 사용자

단, **경험 카드가 등록되지 않았다는 이유만으로 면접 기능의 사용을 제한하지 않는다.**

## 4. 핵심 가치

### 4.1 빠른 면접 시작과 AI 코칭

사용자는 별도의 경험 등록이나 사전 준비 없이 면접을 시작할 수 있다.

AI 면접 평가를 통해 자신의 강점과 보완할 점을 확인하고, 평가 결과를 다음 준비 행동으로 연결할 수 있다.

### 4.2 면접 답변 기반 경험 발견 및 관리 [2차 MVP]

면접 완료 후 전체 답변을 기반으로 AI가 프로젝트와 경험 카드 초안을 생성한다.

사용자는 AI가 발견한 경험을 검토·수정하여 저장하거나, 프로젝트와 경험 카드를 직접 작성할 수 있다.

하나의 프로젝트에 여러 경험 카드를 등록하고, 동일한 경험을 다양한 면접 질문에 활용할 수 있다.

### 4.3 경험의 전략적 활용과 답변 개선 [2차 MVP]

1차 MVP의 답변 개선은 면접 완료 후 평가 · 답변 개선 코칭 · 재도전으로 제공한다 (5.1). 아래 경험 추천 · 퀘스트는 2차 범위다.

면접 질문의 유형과 요구 역량을 기준으로 규칙 기반 경험 추천을 제공한다.

사용자는 질문에 적합한 경험을 비교·선택하고, 강조하려는 역량에 따라 답변을 구성할 수 있다.

평가 결과를 바탕으로 개선 방향을 두 가지로 구분한다.

- **경험 강화:** 실제 경험의 상황, 행동, 판단 근거, 결과 등을 경험 카드에 작성하거나 보완한다.
- **전달 강화:** 면접 답변에서 자신의 경험과 역량을 구체적이고 설득력 있게 설명하도록 개선한다.

경험 카드가 없는 사용자에게도 필요한 퀘스트를 제공할 수 있다.

### 4.4 회차별 성장 기록과 개선 확인

사용자는 공통 면접과 분야별 면접을 반복하여 진행하고, 회사(또는 '기타')·직군별로 누적된 면접 기록을 확인할 수 있다.

동일한 질문이 여러 회차에 출제되더라도 답변과 평가 결과를 독립적으로 보존한다.

재도전 시 최초 답변과 평가를 유지하면서 개선 답변과 새로운 평가를 추가하여 답변의 변화를 확인할 수 있다.

## 5. 핵심 기능 및 요구사항

### 5.1 면접 코칭

사용자는 등록된 경험 카드가 없어도 면접을 시작할 수 있으며, 기존 경험 카드를 참고하거나 경험 카드 없이 답변할 수 있다. (경험 카드 참고는 [2차 MVP]. 1차는 경험 카드 없이 답변한다.)

서비스는 새로운 면접 시작, 기존 데이터 복원, 면접 기록 확인, 평가 결과 확인 및 재도전 기능을 제공한다.

**면접 시작 및 이어하기**

- 사용자는 [+ 새 면접 시작]을 통해 면접 정보 설정 화면으로 진입한다.
- 사용자는 면접 정보 설정에서 회사명, 지원 직군, 면접 유형을 설정한다.
- 회사명은 선택 항목이다. 회사를 지정하지 않고 직군(직무)과 분야만 골라 면접을 시작할 수 있으며, 이 기록은 화면에서 '기타' 그룹으로 분류한다 (0.6).
- 분야별 면접을 선택한 경우 출제할 분야를 설정한다.
- 해당 회사·직군의 기존 면접 데이터가 없는 경우 [면접 시작하기]를 선택한다.
- 동일한 회사·직군의 기존 면접 데이터가 있는 경우 [새로운 회차 시작하기]를 선택한다.
- 동일한 회사에 다른 직군의 데이터만 있는 경우 해당 직군의 첫 면접 회차를 생성한다.
- 새로운 면접 회차는 회사(또는 '기타')·직군을 기준으로 누적하며, 이전 회차의 기록을 보존한다.
- 사용자는 [데이터 저장하기]를 통해 현재 데이터를 Markdown 파일로 내보낼 수 있다.
- 사용자는 [기존 데이터 Markdown 복원]을 통해 저장된 데이터를 불러올 수 있다.
- 복원된 데이터는 저장된 회차 및 기록을 유지하며, 사용자는 해당 데이터를 기반으로 서비스를 이어서 이용할 수 있다.
- Markdown 복원 자체는 새로운 면접 회차를 생성하지 않는다.

**면접 유형 및 질문 구성**

- 사용자는 면접 정보 설정에서 '공통 면접' 또는 '분야별 면접'을 선택할 수 있다.
- 첫 회차부터 공통 면접과 분야별 면접을 자유롭게 선택할 수 있다.
- 공통 면접은 공통 질문 5문항으로 구성한다. ('공통 질문'의 정의 — 질문 은행의 분야가 '공통'인 질문으로 볼지 — 는 미확정, 10.2)
- 분야별 면접은 공통 질문 2문항과 선택한 분야의 질문 3문항으로 구성한다.
- 모든 면접은 총 5문항으로 진행한다.
- 면접 질문은 사전에 준비된 질문 목록에서 선정한다.
- 각 질문에는 공통 질문 또는 분야별 질문의 유형을 구분하여 기록한다.
- 면접 유형은 질문 구성을 결정하며, 회차를 분리하는 기준으로 사용하지 않는다.

**질문 출제 방식**

- 기존 프로토타입의 질문 출제 옵션을 유지한다.
- 사용자는 '새로운 문제만', '섞어서', '똑같은 질문' 중 하나를 선택할 수 있다.
- '새로운 문제만'은 기존에 출제되지 않은 질문을 선정하는 방식이다.
- '섞어서'는 기존 출제 질문과 새로운 질문을 혼합하는 방식이다.
- '똑같은 질문'은 이전 면접에서 출제된 질문을 다시 연습하는 방식이다.
- 사용자는 '회차 선택' 또는 '랜덤 출제' 중 하나를 선택할 수 있다.
- '회차 선택'은 현재 선택한 면접 유형과 동일한 유형의 이전 회차만 선택할 수 있다.
- 분야별 면접은 선택한 분야까지 일치하는 이전 회차만 선택할 수 있다.
- '회차 선택' 시 해당 회차에서 출제된 질문 5문항을 동일하게 출제한다.
- '랜덤 출제'는 이전에 출제된 질문 중 현재 면접 유형과 분야에 적합한 질문을 무작위로 선정한다.
- 공통 면접의 랜덤 출제는 기존 공통 질문 5문항으로 구성한다.
- 분야별 면접의 랜덤 출제는 기존 공통 질문 2문항과 해당 분야의 기존 질문 3문항으로 구성한다.
- '회차 선택'은 현재 면접 유형과 분야가 일치하는 이전 면접 회차가 1개 이상 존재하는 경우 선택할 수 있다.
- 공통 면접의 '랜덤 출제'는 이전에 출제된 서로 다른 공통 질문이 5개 이상 존재하는 경우 선택할 수 있다.
- 분야별 면접의 '랜덤 출제'는 이전에 출제된 서로 다른 공통 질문이 2개 이상, 해당 분야 질문이 3개 이상 존재하는 경우 선택할 수 있다.
- '똑같은 질문'으로 면접을 시작하면 새로운 면접 회차를 생성하며, 이전 회차의 답변과 평가 결과는 변경하지 않는다.
- 동일한 질문이 여러 회차에 출제되는 것을 허용한다.
- 동일 질문은 사전에 준비된 질문 목록의 식별 정보를 기준으로 관리한다.
- 동일 질문의 답변과 평가 결과는 면접 회차별로 독립적으로 저장한다.
- 질문 출제 옵션의 세부 동작은 기존 프로토타입을 유지한다.

**질문 출제 방식의 예외 처리**

- 해당 회사·직군의 이전 면접 기록이 없는 경우 질문 출제 방식 선택 영역을 표시하지 않고 새로운 질문을 자동 출제한다.
- '새로운 문제만'은 해당 면접 유형에 필요한 신규 질문 수가 충분한 경우에만 선택할 수 있다.
- 신규 질문 수가 부족한 경우 '새로운 문제만'을 선택할 수 없도록 한다.
- '섞어서'는 새로운 질문과 기존 출제 질문을 혼합하는 방식이며, 두 유형의 질문이 모두 존재하는 경우 선택할 수 있다.
- '똑같은 질문'은 이전에 출제된 질문을 다시 연습하는 방식으로, 재출제 가능한 질문이 있는 경우에만 선택할 수 있다.
- 공통 질문과 분야별 질문의 출제 이력은 각각 구분하여 관리한다.
- 공통 면접을 진행한 기록이 있지만 분야별 면접은 처음인 경우, '섞어서'의 기존 질문 재출제는 공통 질문에만 적용한다.
- 처음 선택한 분야의 질문 3문항은 새로운 질문으로 출제한다.
- 분야별 면접에서 '새로운 문제만'의 선택 가능 여부는 공통 질문 2문항과 분야별 질문 3문항의 신규 출제 가능 수량을 각각 확인하여 판단한다.

**면접 진행 방식 (1차 확정)**

- 하나의 일관된 면접관 페르소나로 진행한다. 기존 '빠른 피드백' 면접 방식은 1차 목표 구조에서 제거한다.
- 본 질문당 선택적 꼬리질문은 최대 1개다. AI가 더 묻자고 해도 코드가 한도를 지킨다.
- 꼬리질문은 실무 근거 검증(답변의 근거 · 구체성 확인)을 기본으로 하고, 필요할 때 경험 탐색(답변에 드러나지 않은 경험 발굴)에 쓴다.
- 면접 진행 중에는 답변 개선 코칭이나 평가를 제공하지 않는다. 면접관의 반응은 다음 진행을 위한 짧은 반응에 그친다.
- 평가 · 답변 개선 코칭 · 재도전은 면접 완료 후 제공한다.
- 사전 경험 등록이나 경험 카드 없이 면접을 시작할 수 있다. 기존 프로토타입의 '내 경험' 입력을 선택 입력으로 둘지 제거할지는 미확정이다 (10.2).

**주요 요구사항**

- 기존 프로토타입의 면접 진행, 답변 평가, 재도전 기능을 유지한다.
- 기존 프로토타입의 사용자 정의 태그 및 그룹화 기능은 회사별 데이터 관리 구조로 재구성한다. [2차 MVP — 1차는 기존 기능 유지]
- 면접 질문에 적합한 경험을 규칙 기반으로 추천한다. [2차 MVP]
- 사용자는 추천된 경험을 비교하거나 직접 경험을 선택할 수 있다. [2차 MVP]
- 경험 카드에 기록된 내용은 답변 작성의 참고 자료로 활용한다. [2차 MVP]
- 경험 카드가 없는 경우에도 면접 질문에 답변할 수 있다.
- 면접 진행 중에는 경험 카드를 조회·비교·선택·참고할 수 있지만, 생성하거나 수정할 수 없다. [2차 MVP]
- 면접 평가 점수는 사용자가 실제 제출한 답변을 기준으로 산출한다.
- 경험 카드의 내용이나 완성도, 사전에 입력한 경험 내용은 평가 점수에 직접 반영하지 않는다.

**면접 종료 및 평가 생성**

- 5문항 답변 종료 후 질문·답변 데이터를 해당 면접 회차에 저장한다.
- 사용자가 [평가 받기]를 선택하면 AI 평가를 요청한다.
- AI는 위원별 임원 평가(점수, 좋은 점, 뽑지 말아야 할 이유) 및 위원 평균 의견(판단이 갈린 곳, 모두 같은 판단)과 점수, 답변 평가를 수행한다. 퀘스트 생성 · 경험 카드 초안 생성은 [2차 MVP]다.
- AI 평가 응답은 저장 전에 검증한다 (응답 구조 · 평가위원 4명 · 평가 항목 · 점수 타입(정수) · 질문 번호 · ID). 검증에 실패하면 자동으로 1회 다시 요청하고, 그래도 실패하면 평가 오류를 안내한다. 검증에 실패한 결과는 정상 평가로 저장하지 않는다.
- 누락된 평가위원 점수를 0점으로 채우거나, 답변을 다른 질문에 연결하지 않는다. 검증을 통과한 응답에서 범위(위원 0~10 · 기준 0~5)를 벗어난 정수 점수는 경계값으로 보정하고, 합계 · 평균은 보정한 점수로 코드가 계산한다.
- 면접 평가와 경험 카드 초안 생성은 독립적으로 처리한다.
- 한 기능의 처리 실패가 다른 기능의 결과 저장 및 확인을 제한하지 않는다.
- 각 기능의 처리 상태를 구분하여 관리한다.
- 면접 평가가 실패한 경우 평가 완료 상태로 처리하지 않으며, 사용자에게 재시도를 안내한다.
- 면접 평가가 정상적으로 완료된 경우에만 평가 결과를 표시한다.
- 경험 카드 초안 생성 실패 여부는 면접 평가 결과 확인에 영향을 주지 않는다.
- 처리에 실패한 기능은 성공한 결과를 유지한 상태에서 개별적으로 재시도할 수 있다.
- 재시도 시 이미 성공한 결과를 중복 생성하거나 덮어쓰지 않는다.
- AI 평가 결과는 해당 면접 회차의 평가 기록에 연결한다.
- 사용자가 [평가 확인하기]를 선택하면 해당 회사·직군·회차의 면접 기록 확인 화면으로 이동한다. 평가 기록은 그 화면의 LNB 에서 본다.

**면접 기록 (전체)**

- 회사·직군별 전체 회차의 질문과 답변을 통합하여 확인할 수 있다.
- 공통 면접과 분야별 면접의 기록을 동일한 회차 체계로 관리한다.
- 각 회차의 질문과 최초 답변은 독립적으로 저장한다.
- 동일한 질문이 여러 회차에 출제되더라도 답변을 회차별로 누적한다.
- 동일한 질문의 이전 회차 답변과 최신 회차 답변을 함께 확인할 수 있다.
- 각 답변이 작성된 회차와 면접 유형을 확인할 수 있다.
- 새로운 회차가 추가되어도 기존 질문·답변 기록은 변경되지 않는다.
- 이번 MVP에서는 암기용 답변 선택·수정 및 삭제 태그 기능을 제공하지 않는다. (기존 프로토타입에 있는 암기 탭 · 지운 지난 답 기능의 1차 처리는 미확정, 10.2)

**평가 기록 (회차별)**

- 면접 평가 결과는 해당 회차를 기준으로 저장한다.
- 각 회차의 최초 면접 평가 점수와 평가 내용을 확인할 수 있다.
- 모의 결과, 위원별 임원 평가, 답변별 평가를 확인할 수 있다. (퀘스트, 경험 카드 초안은 [2차 MVP])
- 새로운 면접 회차가 추가되어도 이전 회차의 평가 결과는 유지한다.
- 재도전으로 새로운 평가 결과가 생성되어도 최초 회차의 평가 점수와 평가 내용은 변경되지 않는다.
- 경험 카드의 생성·수정 및 저장 여부는 기존 면접 평가 결과에 영향을 주지 않는다.

**면접 회차 및 데이터 누적**

- 새로운 면접 회차는 [+ 새 면접 시작]에서 생성한다.
- 면접 회차는 회사명과 지원 직군의 조합을 기준으로 관리한다.
- 동일한 회사·직군에서 새로운 면접을 시작하면 다음 회차로 누적한다.
- 공통 면접과 분야별 면접은 별도의 회차 번호를 부여하지 않는다.
- 면접 유형을 변경하더라도 동일 회사·직군 내에서는 회차를 통합하여 누적한다.
- 다른 직군으로 면접을 시작하면 해당 직군의 회차를 별도로 관리한다.
- 해당 직군의 기존 면접 기록이 없으면 1회차부터 시작한다.
- 해당 직군의 기존 면접 기록이 있으면 다음 회차로 누적한다.
- 다른 직군으로 면접을 시작하더라도 기존 직군의 면접 기록은 유지한다.
- 기존 면접 기록의 직군명을 수정하는 기능은 제공하지 않는다.
- 각 회차에는 선택한 면접 유형과 실제 출제된 질문 유형을 기록한다.
- 각 회차의 질문·답변·평가 결과는 독립적으로 저장한다.
- 동일한 질문이 여러 회차에 출제되더라도 답변과 평가 결과는 회차별로 별도 저장한다.
- 전체 회차의 면접 데이터를 통합하여 관리한다.
- 통합된 데이터를 기반으로 공통 질문과 분야별 질문의 평가 및 진행도를 구분하여 확인할 수 있다.
- 이전 회차의 답변과 평가 결과는 새로운 회차를 진행하더라도 유지한다.
- 이번 MVP에서는 이전 회차의 원본 답변 삭제 기능을 제공하지 않는다.

**재도전 (전체)**

- 재도전은 새로운 면접 회차를 생성하지 않는다. 기존 회차에 속한 답변 개선 이력이며 회차 번호를 늘리지 않는다.
- **재도전 횟수 제한은 없다.** 같은 질문에 횟수 제한 없이 재도전할 수 있으며, 횟수 초과 차단 · 남은 횟수 표시 · 제한용 카운터를 두지 않는다.
- 새 회차를 진행하지 않아도 Markdown 복원 후 기존 회사 · 직군 · 회차를 골라 바로 재도전할 수 있다 (6.7).
- 재도전 기록은 해당 회차(`round_id`)와 질문(`question_id`)에 연결하고, 기록마다 고유 ID(`attempt_id`)를 둔다. 재도전 순서는 저장된 기록으로 계산한다.
- 재도전 답변은 제출 시점의 답변을 기준으로 평가하고, 평가 결과는 별도 기록으로 저장한다.
- 사용자는 전체 회차의 질문과 답변을 확인하고 재도전할 질문을 선택할 수 있다.
- 재도전은 선택한 회차의 기존 질문·답변에 연결된다.
- 사용자는 기존 답변에 대한 코칭을 확인하고 개선 답변을 작성할 수 있다.
- 재도전 시 개선 답변에 대한 새로운 평가를 수행한다.
- 최초 답변과 최초 평가 결과는 변경하지 않는다.
- 재도전 답변과 평가 결과는 기존 질문에 개선 이력으로 누적한다.
- 사용자는 최초 답변과 재도전 답변을 비교할 수 있다.
- 사용자는 최초 평가 점수와 재도전 평가 점수를 비교할 수 있다.
- 재도전 점수는 선택한 회차의 해당 질문에 연결된 최초 답변 및 재도전 답변을 기준으로 비교한다.
- 현재 답변은 해당 질문의 재도전 이전 최고 점수와 비교한다.
- 다른 회차에 동일한 질문이 출제되었더라도 해당 회차의 최고 점수 계산에는 포함하지 않는다.
- 다른 회차에 동일 질문의 더 높은 점수가 존재하는 경우, 해당 점수와 회차를 참고 정보로 제공한다.
- 사용자는 다른 회차의 동일 질문 답변과 평가 기록을 확인할 수 있다.
- 현재 점수가 기존 최고 점수보다 높으면 새로운 최고 점수로 갱신한다.
- 현재 점수가 기존 최고 점수보다 낮으면 점수 하락을 그대로 기록한다.
- 각 재도전의 점수와 평가 결과는 독립적으로 저장한다.
- 점수 변화는 동일한 질문과 평가 기준을 바탕으로 산출한다.
- 사용자는 평가 항목별 점수 변화와 답변 내용의 개선 여부를 함께 확인할 수 있다.
- 재도전 결과는 평가 기록(회차별)의 최초 평가 점수를 변경하지 않는다.
- 재도전은 경험 카드 생성이나 퀘스트 수행 여부와 관계없이 이용할 수 있다.
- 원본 답변과 기존 재도전 기록은 삭제하거나 덮어쓰지 않는다.

**AI 답변 개선 코칭**

- AI는 기존 면접 질문과 사용자의 실제 답변을 바탕으로 개선 방향을 제안한다.
- AI는 답변의 근거, 구체성, 차별성, 전달력 등을 보완할 수 있는 코칭 질문을 제안할 수 있다.
- 코칭 질문은 새로운 면접 출제 문항으로 취급하지 않는다.
- 코칭 질문은 기존 면접 질문 및 평가 결과에 연결하여 관리한다.
- 사용자는 AI 코칭을 참고하여 기존 질문에 대한 개선 답변을 작성할 수 있다.
- AI는 사용자 답변에 없는 경험이나 성과를 임의로 생성하지 않는다.
- AI는 각 답변을 이전 답변 및 평가 점수와 독립적으로 평가한다.
- AI 평가 점수는 현재 제출한 답변과 동일한 평가 기준을 바탕으로 산출한다.
- 이전 답변 및 평가 점수는 현재 답변의 점수 산출에 영향을 주지 않는다.
- 평가 완료 후 기존 최고 점수 답변과 현재 답변을 비교하여 개선된 부분과 보완할 부분을 설명한다.
- AI 비교 코칭은 점수 산출과 분리하여 수행한다.
- 점수가 상승하거나 하락한 경우 평가 항목별 변화와 답변 내용의 차이를 함께 설명한다.

세부 요구사항은 `features/02-interview.md`에서 정의한다.

### 5.2 AI 경험 카드 초안 생성 [2차 MVP]

> 2차 MVP 범위다. 1차는 이 기능을 구현하지 않으며, 1차 데이터 구조는 최초 답변 · 질문 ID · 회차 ID를 보존해 2차 연결을 막지 않는다.

사용자는 면접을 완료한 후 자신의 답변을 바탕으로 AI가 제안한 프로젝트 및 경험 카드 초안을 검토할 수 있다.

**주요 요구사항**

- 사용자가 면접 완료 후 [평가 받기] 버튼을 선택하면 기존 면접 평가와 전체 답변 기반 AI 경험 분석을 실행한다.
- AI는 해당 면접 회차의 전체 최초 답변을 일괄 분석하여 프로젝트와 개별 경험을 분류한다.
- AI는 프로젝트 초안과 프로젝트별 경험 카드 초안을 함께 생성한다.
- AI는 프로젝트와 경험을 구분하여 분석한다.
- 동일한 프로젝트에서 발생한 동일한 사건·행동이 여러 답변에서 발견되면 하나의 경험 카드 초안으로 통합하여 제안한다.
- 동일한 프로젝트라도 서로 다른 사건·행동이 발견되면 별도의 경험 카드 초안으로 구분한다.
- 서로 다른 프로젝트에서 발견된 경험은 프로젝트별로 구분한다.
- 동일한 경험을 여러 답변에서 추출한 경우 근거가 된 질문과 답변을 모두 연결한다.
- 경험의 동일 여부를 판단하기 어려운 경우 자동 통합하지 않고 사용자에게 확인이 필요한 항목으로 표시한다.
- 사용자는 AI가 제안한 프로젝트·경험의 분류와 경험 통합 여부를 검토·수정할 수 있다.
- 각 경험 카드 초안에는 근거가 된 면접 질문과 실제 답변을 연결한다.
- 경험 추출의 근거가 된 답변 부분을 하이라이트하여 표시한다.
- 프로젝트를 식별할 수 없는 경험은 '프로젝트 미지정'으로 분류한다.
- 경험은 식별되지만 정보가 부족한 항목은 빈칸 또는 '추가 작성 필요'로 표시한다.
- 구체적인 경험을 식별할 수 없는 답변은 '경험 추출 어려움 - 보완 필요'로 분류하고 임의의 경험 카드를 생성하지 않는다.
- AI는 답변에 없는 경험, 역할, 성과, 수치를 임의로 생성하지 않는다.
- AI가 생성한 경험 카드 초안이 기존 경험 카드와 유사한 경우 기존 카드 보완을 제안한다.
- 유사성 판단은 프로젝트명뿐 아니라 사건과 행동의 내용을 기준으로 한다.
- 유사한 기존 카드가 발견되더라도 AI가 자동으로 통합하거나 덮어쓰지 않는다.
- 사용자는 기존 카드 보완, 새 카드로 저장, 저장하지 않기 중 처리 방식을 선택할 수 있다.
- 사용자가 결정을 미루는 경우 초안은 '검토 대기' 상태로 유지한다.
- 기존 카드 보완을 선택한 경우 변경 내용을 비교하고 사용자가 승인한 항목만 반영한다.

**경험 카드 초안 확인 및 저장**

- 경험 카드 초안은 면접 평가 결과와 함께 생성한다.
- 사용자는 면접 코칭의 [평가 기록]에서 [경험 카드 초안]을 확인할 수 있다.
- 경험 카드 초안을 선택하면 경험 관리의 [경험 상세 편집] 화면으로 이동한다.
- 사용자는 경험 상세 편집 화면에서 AI가 제안한 프로젝트 및 경험 카드 초안을 검토·수정할 수 있다.
- 저장 방식은 새 경험 카드로 저장, 기존 경험 카드 보완, 저장하지 않기로 구분한다.
- 기존 경험 카드를 보완할 때는 변경 내용을 비교·확인한 후 저장한다.
- 프로젝트 초안은 사용자가 검토·확인한 경우에만 정식 프로젝트로 저장한다.
- AI는 사용자의 명시적인 확인 없이 정식 프로젝트나 경험 카드를 등록·수정·덮어쓰지 않는다.
- 경험 카드 초안 생성에 실패하더라도 정상적으로 완료된 면접 평가 결과는 유지한다.
- 경험 카드 초안 생성에 실패한 경우 사용자는 해당 기능만 다시 실행할 수 있다.
- AI 경험 분석은 완료됐지만 추출할 경험이 없는 경우 '생성된 경험 카드가 없습니다. 직접 경험 카드를 추가하고 관리해 보세요.'라는 안내와 [경험 관리로 이동] 버튼을 제공한다.
- 경험 카드 초안 생성 과정에서 기술적 오류가 발생한 경우 실패 상태와 [다시 시도] 버튼을 제공한다.
- 경험 카드 초안이 생성되지 않아도 정상적으로 완료된 면접 평가 결과는 확인할 수 있다.
- 재시도는 해당 면접 회차의 기존 답변을 기준으로 수행한다.
- 재시도 과정에서 기존 면접 평가 결과를 변경하지 않는다.
- 새 경험 카드로 저장하는 경우 사용자가 선택한 프로젝트에 새로운 경험 카드를 생성한다.
- 사용자는 AI가 제안한 프로젝트 대신 기존 프로젝트를 선택할 수 있다.
- 기존 경험 카드 보완을 선택하면 사용자가 보완할 경험 카드를 직접 선택한다.
- 기존 카드의 내용은 기본적으로 유지하며, AI 초안에서 발견한 정보는 변경 후보로 표시한다.
- 사용자는 항목별 변경 내용을 비교하고 반영할 내용을 선택할 수 있다.
- 사용자가 저장을 확정한 경우에만 선택한 변경 내용을 기존 경험 카드에 반영한다.
- 기존 경험 카드의 내용은 사용자 확인 없이 자동으로 삭제하거나 교체하지 않는다.
- 기존 카드 보완 시 AI 초안의 근거가 된 면접 질문과 답변의 연결 관계를 유지한다.
- 저장하지 않기를 선택한 초안은 정식 프로젝트나 경험 카드로 등록하지 않는다.
- 경험 카드 저장 및 보완은 기존 면접 답변과 평가 결과를 변경하지 않는다.
- AI 경험 카드 초안은 최초 '검토 대기' 상태로 생성한다.
- 사용자가 새 경험 카드로 저장하거나 기존 경험 카드 보완을 완료하면 '저장 완료'로 변경한다.
- 사용자가 저장하지 않기를 선택하면 '저장하지 않음'으로 변경한다.
- '검토 대기'는 사용자가 아직 저장 여부를 결정하지 않은 상태를 의미한다.
- '저장하지 않음'은 사용자가 정식 경험 카드로 등록하지 않기로 결정한 상태를 의미한다.
- '검토 대기' 초안은 이후 다시 검토할 수 있도록 유지한다.
- '저장하지 않음' 초안은 검토 대기 목록에서 제외하고 처리 상태를 보존한다.
- 일부 초안의 처리 여부는 다른 초안의 상태에 영향을 주지 않는다.
- 사용자가 저장을 승인하지 않은 초안은 정식 경험 카드로 등록하지 않는다.

AI 경험 카드 초안의 생성 규칙은 `technical/AI_RULES.md`, 검토·저장 기능은 `features/03-experience.md`에서 정의한다.

### 5.3 경험 관리 [2차 MVP]

> 2차 MVP 범위다. 1차에서는 경험 카드 없이 면접을 진행한다.

사용자는 프로젝트와 경험 카드를 직접 작성·수정하고, 면접 답변을 통해 발견한 경험을 추가로 기록할 수 있다.

**주요 요구사항**

- 하나의 프로젝트에 여러 경험 카드를 등록할 수 있다.
- 경험 카드는 상황, 행동, 판단 근거, 결과, 역량 태그 등을 관리할 수 있다.
- 동일한 경험 카드를 여러 면접 질문과 답변에서 활용할 수 있다.
- 경험 관리 기능은 면접 진행 여부와 관계없이 독립적으로 이용할 수 있다.
- 면접 질문·답변 진행 중에는 기존 프로젝트와 경험 카드를 조회·비교·선택·참고할 수 있지만, 등록하거나 수정할 수 없다.
- 면접 평가 이후 경험 관리의 [경험 상세 편집] 화면에서 프로젝트와 경험 카드를 생성·수정할 수 있다.
- 경험 카드의 생성·수정은 면접 진행이나 재도전의 필수 조건이 아니다.

세부 요구사항은 `features/03-experience.md`에서 정의한다.

### 5.4 퀘스트 (Quest) [2차 MVP]

> 경험 강화 퀘스트는 2차 MVP 범위다. 1차는 기존 프로토타입의 '역전의 실마리'(평가 후 가장 낮은 답과 약한 기준을 짚어 재도전으로 연결)를 유지한다. '역전의 실마리'를 1차에서 '퀘스트(전달 강화)'로 전환할지는 미확정이다 (10.2).

면접 평가 결과에 따라 사용자가 개선할 부분을 확인하고 필요한 행동을 수행할 수 있도록 돕는다.

기존 프로토타입의 '역전의 실마리' 기능을 '퀘스트'로 변경한다.

**퀘스트 유형**

- **경험 강화:** 실제 경험의 상황, 행동, 판단 근거, 결과 등을 경험 카드에 작성하거나 보완한다.
- **전달 강화:** 면접 답변에서 자신의 경험과 역량을 구체적이고 설득력 있게 설명하도록 개선한다.

**주요 요구사항**

- 기존 프로토타입의 퀘스트 기능을 유지한다.
- 평가 결과에 따라 필요한 유형의 퀘스트를 제공한다.
- 면접 코칭의 [답변별 평가]에서 퀘스트를 확인할 수 있다.
- 평가 결과 화면에서 퀘스트 발생 여부와 개수를 확인할 수 있다.
- 퀘스트로 이동할 수 있는 바로가기 버튼을 제공한다.
- 두 가지 유형의 퀘스트를 반드시 모두 수행할 필요는 없다.
- 경험 카드 생성과 퀘스트 수행은 독립적인 기능으로 관리한다.
- 퀘스트를 수행하지 않아도 경험 카드를 생성하거나 면접에 재도전할 수 있다.

세부 요구사항은 `features/02-interview.md`에서 정의한다.

### 5.5 취업 관리 (Schedule) [2차 MVP]

> 지망 태그 · 지원 정보 · 일정 · 회사명 변경 UI는 2차 MVP 범위다. 단, 회사 · 직군 식별과 회차 누적(아래 '회사별 데이터 관리'의 식별 규칙과 '면접 데이터 연동')은 1차 면접 기록에 필요하므로 1차 범위다 (0.6). 1차는 기존 프로토타입의 사용자 정의 그룹 · 태그 기능을 그대로 유지한다.

사용자는 회사별 지원 정보와 일정을 관리하고, 회사명에 따라 자동으로 통합된 면접 데이터를 확인할 수 있다.

**회사별 데이터 관리**

- 회사명을 기준으로 면접 및 지원 데이터를 자동 그룹화한다.
- 회사명은 앞뒤 공백만 제거한 값(`company_key`)이 정확히 일치하는 경우에만 동일 회사로 인식한다. 중간 공백과 대소문자는 바꾸지 않는다.
- 회사는 고유 ID(`company_id`)로 식별하고, 표시 이름(`company_name`)과 비교용 키(`company_key`)를 구분한다.
- 회사명이 일치하지 않으면 별도의 회사 데이터로 관리한다.
- 회사를 지정하지 않은 면접 기록은 '기타' 그룹으로 분류한다. '기타' 그룹은 회사 미지정 상태를 뜻하며, 실제 회사명이 '기타'인 회사와 구분한다. (1차 범위, 0.6)
- 동일한 회사명의 데이터는 공통 면접과 분야별 면접을 구분하지 않고 하나의 회사 그룹에 통합한다.
- 동일 회사에 서로 다른 직군이 있는 경우 직군별 하위 그룹을 생성한다.
- 지원 정보와 일정은 회사·직군별로 독립적으로 관리한다.
- 회사별 데이터는 면접 코칭과 취업 관리에서 공통으로 참조한다.
- 기존 회사명을 수정하는 경우 연결된 면접 기록도 변경된 회사명으로 관리한다. [2차 MVP — 회사명 변경 UI]
- 회사명 변경 시 기존 면접 회차와 질문·답변·평가 결과의 연결 관계를 유지한다. 면접 기록은 회사명이 아니라 `company_id` 로 연결하므로, 1차 구조에서 이 연결을 유지할 수 있다.
- 회사명 변경 기능의 구체적인 구현 방식(화면 · 충돌 처리)은 2차에서 확정한다.

**지망 태그 관리**

- 기존 프로토타입의 사용자 정의 태그 생성 및 분류 기능을 활용한다.
- 사용자는 1지망, 2지망 등 지망 태그를 직접 생성할 수 있다.
- 지망 태그는 회사별로 설정한다.
- 동일 회사에 여러 직군이 등록되어도 지망 태그는 회사 단위로 관리한다.
- 사용자는 지망 태그를 기준으로 회사를 분류하고 확인할 수 있다.

**지원 정보 및 일정 관리**

- 전체 지원 현황 및 일정을 확인할 수 있다.
- 회사별 지원 데이터를 선택할 수 있다.
- 동일 회사에 여러 직군이 있는 경우 직군별 지원 정보와 일정을 구분한다.
- 취업 관리에 등록된 회사 및 직군 정보는 면접 정보 설정에서 참조할 수 있다.
- 지원 정보와 일정은 면접 회차와 별도로 관리한다.
- 지원 상태 단계는 **기존 요구사항 후보**로 `준비 → 지원 → 대기 → 면접 → 결과` 를 둔다. 단계별 정의 · 명칭, 상태 변경 방식, 지원 마감일 · 면접일 등 일정과의 연동 방식은 2차 MVP에서 확정한다 (`features/04-schedule.md`).

**면접 데이터 연동** (1차 범위)

- 면접 데이터는 회사(`company_id`, 회사 미지정이면 '기타' 그룹)와 직군(직무)을 기준으로 연결한다.
- 공통 면접과 분야별 면접은 동일한 회차 체계로 통합 관리한다.
- 공통 면접은 공통 질문 5문항으로 구성한다.
- 분야별 면접은 공통 질문 2문항과 분야별 질문 3문항으로 구성한다.
- 면접 유형과 관계없이 새로운 면접을 시작할 때마다 다음 회차로 누적한다.
- 회차는 고유 ID(`round_id`)로 식별하고, 사용자에게는 회사(또는 '기타')·직군별 회차 번호(`round_number`)를 보여 준다.
- 각 회차의 질문·답변·평가 결과는 독립적으로 저장한다.
- 동일한 질문이 여러 회차에 출제되더라도 답변과 평가 결과를 회차별로 누적한다. 같은 질문은 질문 ID(`question_id`)로 연결한다.
- 전체 회차의 면접 데이터를 통합하여 관리한다.
- 통합된 면접 기록에서 공통 질문과 분야별 질문의 평가 및 진행도를 구분하여 확인할 수 있다.
- 재도전은 새로운 회차를 생성하지 않고 기존 답변에 개선 이력을 추가한다. 횟수 제한은 없다.
- 재도전 결과는 기존 회차의 최초 평가 결과를 변경하지 않는다.
- 회사별 면접 기록 및 평가 결과는 면접 코칭에서 확인할 수 있다.
- 암기용 답변 선택·수정 및 삭제 태그 기능은 이번 MVP에 포함하지 않는다. (기존 프로토타입 암기 기능의 1차 처리는 미확정, 10.2)

세부 요구사항은 `features/04-schedule.md`에서 정의한다.

### 5.6 Markdown 저장 및 불러오기

**1차 MVP 저장 · 복원 (확정)**

- 사용자는 [데이터 저장하기]로 **전체 기록을 하나의 Markdown v2 파일**로 저장한다. 파일 하나에 여러 회사 · 직군 · 회차가 함께 들어간다.
- 파일에는 사람이 읽는 Markdown 본문과 복원용 데이터를 함께 담는다. 복원용 데이터는 기존 `interview-data` 태그를 유지하고 `version: 2` 를 쓴다.
- 저장 내용: 회사 · 직군 · 회차, 질문(질문 ID · 당시 문구), 원본 답변, 평가 결과, 재도전 답변과 평가 이력.
- 사용자는 [기존 데이터 Markdown 복원]으로 v2 파일과 기존 v1 파일을 불러올 수 있다. 지원하지 않는 버전은 안내하고 안전하게 거부한다.
- 같은 기록을 반복해 불러와도 회차가 중복 생성되거나 기존 기록이 자동으로 덮어써지지 않는다.
- 저장은 새 파일 다운로드이며 기존 파일을 자동으로 덮어쓰지 않는다.
- 과거 면접 · 평가 · 재도전 기록은 저장 · 복원 후에도 당시 상태를 유지한다.
- 진행 중이던 면접(평가 전)의 저장 · 질문 단위 재개 방식은 미확정이다 (10.2).

**2차 MVP 확장 (방향만 확정)**

- 선택 저장 기능은 향후 확장 방향으로 유지한다. 선택 저장 단위 · 화면 구성 · 선택 방식 · 저장 대상 제외 방식 · 저장 전 확인 절차 · 선택 저장과 삭제의 관계는 **미확정**이다.
- 아래 경험 관리 · AI 초안 · 취업 관리 데이터의 저장 · 내보내기 유형은 2차 기능과 함께 확정한다. v2 형식은 이 항목들을 더할 수 있도록 설계한다.

- 사용자는 면접 기록, 경험 관리 정보 및 취업 관리 데이터를 Markdown 파일로 저장하고, 저장된 파일을 복원하여 서비스를 이어서 이용할 수 있다. [경험 · 취업 관리 데이터는 2차 MVP]
- '검토 대기' 상태의 AI 초안은 정식 경험 관리 데이터와 구분하여 관리한다.
- 경험 관리만 내보내기에는 정식 저장된 프로젝트와 경험 카드만 포함한다.
- 경험 + 면접 통합 내보내기에는 '검토 대기' 초안의 내용과 상태를 포함하여 복원할 수 있도록 한다.
- '저장하지 않음' 상태의 초안은 정식 경험 카드로 내보내지 않으며, 통합 내보내기에는 처리 상태만 기록한다.
- Markdown 복원 시 AI 초안의 처리 상태를 유지한다.
- 복원된 '검토 대기' 초안은 사용자가 이어서 검토할 수 있다.
- 복원된 '저장하지 않음' 항목은 검토 대기 목록에 다시 표시하지 않는다.

**내보내기 유형** [2차 MVP — 1차는 위 '전체 기록 v2 저장' 하나]

1. **경험 관리만 내보내기**
   - 프로젝트 및 저장 완료된 경험 카드
   - 경험 카드 상태와 역량 태그
   - 연결된 퀘스트(선택)
   - 면접 진행 여부와 관계없이 내보내기 가능

2. **경험 + 면접 통합 내보내기**
   - 프로젝트 및 저장 완료된 경험 카드
   - 지원 회사 및 직군 정보
   - 회사·직군별 전체 면접 회차와 질문
   - 답변 및 평가 결과
   - 재도전 답변과 평가 이력
   - 경험 강화·전달 강화 퀘스트
   - 진행 중인 면접도 내보낼 수 있으며 미완료 항목을 명시
   - '검토 대기' 상태의 AI 초안 내용 및 처리 상태
   - '저장하지 않음' 상태의 AI 초안 처리 기록 (초안 내용 제외)

3. **면접 기록만 내보내기**
   - 1차의 '전체 기록 v2 저장'이 이 범위(면접 회차, 질문, 답변, 평가 결과, 재도전 이력)를 담는다
   - 기존 v1 면접 리포트(회차 1개 = 파일 1개)는 읽기 호환만 유지한다

**Markdown 복원 및 이어하기**

- 사용자는 [데이터 저장하기]를 통해 현재 서비스 데이터를 Markdown 파일로 내보낼 수 있다.
- 사용자는 [기존 데이터 Markdown 복원]을 통해 저장된 Markdown 파일을 불러올 수 있다.
- 복원된 데이터는 저장 당시의 면접 회차, 답변, 평가 결과 및 재도전 이력을 유지한다.
- 복원된 데이터에 포함된 경험 카드와 취업 관리 정보도 함께 복구한다. [2차 MVP]
- Markdown 복원 자체는 새로운 면접 회차를 생성하지 않는다.
- 사용자는 복원된 데이터를 기반으로 기존 기록을 확인하거나, 기존 회차에서 바로 재도전하거나, 새로운 면접을 시작할 수 있다.
- 진행 중이던 면접의 질문 단위 재개 방식은 미확정이다 (10.2).

**공통 원칙**

- 사용자가 저장하지 않은 AI 프로젝트·경험 카드 초안은 정식 경험 관리 Markdown 내보내기에 포함하지 않는다.
- 사용자가 검토·저장한 경험 카드는 일반 경험 카드와 동일하게 내보낼 수 있다.
- Markdown 내보내기는 파일 다운로드이며, 서비스 내부 저장·자동저장과 구분한다.
- 이번 MVP의 Markdown 저장 기능은 사용자가 현재 작업 데이터를 백업하고 이후 복원하기 위한 수동 저장 방식이다.
- 사용자가 프로젝트·경험 카드·면접 기록·취업 관리 데이터를 추가하거나 수정하면 현재 작업 데이터에 반영한다.
- 브라우저 종료 또는 작업 세션 종료 시 백업하지 않은 데이터는 소실될 수 있다.
- 사용자는 변경된 데이터를 보존하기 위해 [데이터 저장하기]로 Markdown 파일을 다시 다운로드할 수 있다.
- Markdown 복원 시 백업 파일에 포함된 데이터를 기준으로 작업을 이어서 진행한다.
- 기존 Markdown v1 파일을 통한 데이터 복원 기능을 유지한다. 지원 · 부분 복원 · 거부 형식은 `MIGRATION.md` 를 따른다.
- 경험 관리 데이터를 포함한 v2 파일의 불러오기 범위는 2차 기능과 함께 확정한다.
- 데이터 저장 및 복원 과정에서 기존 면접 회차와 재도전 이력의 관계를 유지한다.
- 원본 면접 평가와 재도전 평가의 구분을 유지한다.

세부 데이터 형식은 `technical/DATA_MODEL.md`에서 정의한다.

## 6. 핵심 사용자 흐름

서비스는 새로운 면접 시작과 기존 Markdown 데이터 복원이라는 두 가지 주요 진입 경로를 제공한다.

사용자는 경험 카드를 사전에 등록하지 않아도 면접을 시작할 수 있으며, 서비스 내부에서는 면접 코칭, 경험 관리, 취업 관리 기능을 독립적으로 이용할 수 있다.

### 6.1 새로운 면접을 시작하는 경우

```text
서비스 접속
    ↓
스플래시
    ↓
시작 화면 (유저 닉네임 자동 생성 — 1차 포함 여부 미확정)
    ↓
+ 새 면접 시작
    ↓
면접 정보 설정
    ├── 회사명 (선택 · 지정하지 않으면 '기타' 그룹)
    ├── 지원 직군
    ├── 면접 유형
    │     ├── 공통 면접
    │     │      └── 공통 질문 5문항
    │     │
    │     └── 분야별 면접
    │            ├── 분야 선택
    │            └── 공통 질문 2문항 + 분야별 질문 3문항
    │
    ├── 질문 출제 방식
    │
    ├── 새로운 문제만
    │
    ├── 섞어서
    │
    └── 똑같은 질문
          │
          ├── 회차 선택
          │     ↓
          │   동일 면접 유형 확인
          │     ↓
          │   분야별 면접인 경우 동일 분야 확인
          │     ↓
          │   이전 회차 선택
          │     ↓
          │   해당 회차의 질문 5문항 재출제
          │
          └── 랜덤 출제
                ↓
              면접 유형 및 분야 확인
                ↓
              기존 출제 질문 중 무작위 선정
    ↓
기존 회사·직군 면접 데이터 확인
    │
    ├── 해당 회사·직군의 면접 데이터 없음
    │       ↓
    │   면접 시작하기
    │       ↓
    │   1회차 생성
    │
    └── 해당 회사·직군의 면접 데이터 있음
            ↓
        새로운 회차 시작하기
            ↓
        다음 회차 생성
    ↓
5문항 면접
    ↓
질문 확인
    ↓
경험 카드 참조 (선택 · 2차 MVP)
    ↓
답변 작성
    ↓
5문항 답변 종료
    ↓
평가 받기
    ↓
AI 평가 및 후속 결과 생성
    ↓
평가 확인하기
```

**주요 원칙**

- 프로젝트나 경험 카드를 등록하지 않아도 면접을 시작할 수 있다.
- 면접 유형에 따라 질문 구성을 결정한다.
- 공통 면접은 공통 질문 5문항으로 구성한다.
- 분야별 면접은 공통 질문 2문항과 분야별 질문 3문항으로 구성한다.
- 모든 면접은 총 5문항으로 진행한다.
- 면접 회차는 회사(또는 '기타')·직군을 기준으로 통합 관리한다.
- 면접 유형이 달라도 별도의 회차 번호를 부여하지 않는다.
- 동일한 회사에 다른 직군의 면접 데이터만 있는 경우 해당 직군의 첫 회차를 생성한다.
- 새로운 회차를 시작하더라도 이전 회차의 질문·답변·평가 기록은 보존한다.
- 면접 진행 중에는 기존 경험 카드를 참고할 수 있다.
- 경험 카드가 없는 경우에도 답변을 작성할 수 있다.
- 면접 질문은 사전에 준비된 질문 목록에서 사용자가 선택한 출제 방식에 따라 선정한다.

### 6.2 기존 Markdown 데이터를 복원하는 경우

```text
서비스 접속
    ↓
스플래시
    ↓
시작 화면
    ↓
기존 데이터 Markdown 복원
    ↓
저장된 Markdown 파일 불러오기
    ↓
기존 데이터 복원
    ↓
GNB 1 · 홈 (Home)
    ↓
기존 기록 확인 또는 서비스 이용
```

**주요 원칙**

- 사용자는 [데이터 저장하기]로 내보낸 Markdown 파일을 복원할 수 있다.
- 복원된 데이터는 기존 면접 회차와 질문·답변·평가 기록을 유지한다.
- 복원된 데이터에 포함된 경험 카드와 취업 관리 정보도 함께 복구한다.
- 기존 재도전 이력이 있는 경우 해당 이력도 유지한다.
- Markdown 복원 자체는 새로운 면접 회차를 생성하지 않는다.
- 사용자는 복원된 데이터를 기반으로 기존 기록을 확인하거나 새로운 면접을 시작할 수 있다.
- 진행 중이던 면접의 질문 단위 재개 방식은 데이터 저장 구조 검토 후 확정한다.

### 6.3 면접 질문 및 답변 진행

```text
면접 유형에 따른 5문항 구성
    │
    ├── 공통 면접
    │      └── 공통 질문 5문항
    │
    └── 분야별 면접
           ├── 공통 질문 2문항
           └── 분야별 질문 3문항
    ↓
질문 확인
    ↓
기존 경험 카드 데이터 확인
    │
    ├── 경험 카드 없음
    │       ↓
    │   비교할 경험 카드 없음
    │
    └── 경험 카드 있음
            ↓
        경험 추천 / 비교 확인
    ↓
답변 작성
    ↓
면접관 반응 (필요하면 꼬리질문 1개 → 답변)
    ↓
다음 질문
    ↓
5문항 답변 종료
```

'기존 경험 카드 데이터 확인' 단계는 [2차 MVP]다. 1차는 질문 확인 후 바로 답변을 작성한다.

**주요 원칙**

- 각 질문에는 공통 또는 분야별 질문 유형과 질문 ID를 기록한다.
- 하나의 면접관 페르소나가 진행하며, 본 질문당 선택적 꼬리질문은 최대 1개다. 꼬리질문은 실무 근거 검증을 기본으로 하고 필요할 때 경험 탐색에 쓴다.
- 면접 진행 중에는 답변 개선 코칭이나 평가를 제공하지 않는다.
- 경험 카드가 있는 경우 질문에 적합한 경험을 규칙 기반으로 추천한다. [2차 MVP]
- 사용자는 추천된 경험을 비교하거나 직접 경험을 선택할 수 있다. [2차 MVP]
- 경험 카드의 내용은 답변 작성을 위한 참고 자료로 활용한다. [2차 MVP]
- 면접 질문·답변 진행 중에는 기존 경험 카드를 조회·비교·선택·참고할 수 있다. [2차 MVP]
- 면접 진행 중에는 프로젝트나 경험 카드를 새로 생성하거나 수정할 수 없다.
- 경험 카드가 없어도 면접을 정상적으로 진행할 수 있다.
- 면접 평가 점수는 사용자가 실제 제출한 답변을 기준으로 산출한다.
- 동일한 질문이 이전 회차에 출제되었더라도 현재 회차의 답변은 독립적으로 저장한다.

### 6.4 면접 종료 및 평가 결과 확인

```text
5문항 답변 종료
    ↓
해당 회차의 면접 기록 저장
    ↓
평가 받기
    ↓
AI 처리 요청
    │
    ├── 면접 평가 처리
    │     ├── 위원별 임원 평가
    │     ├── 답변별 평가
    │     └── 퀘스트 생성 (2차 MVP)
    │
    ├── 경험 카드 초안 생성 (2차 MVP)
    │     └── 프로젝트 및 경험 분석
    │
    ↓
기능별 처리 상태 확인
    │
    ├── 면접 평가
    │     ├── 성공 (응답 검증 통과) → 평가 결과 저장
    │     └── 실패 (오류 · 형식 오류 · 위원 / 항목 누락 · 점수 타입 · 번호 불일치) → 자동 재시도 1회 → 그래도 실패하면 오류 안내 및 평가 재시도
    │
    ├── 경험 카드 초안 생성 (2차 MVP)
    │     ├── 성공 → 초안 저장
    │     └── 실패 → 초안 미생성 안내
    ↓
면접 평가 성공 여부 확인
    │
    ├── 성공 → 평가 확인하기
    │
    └── 실패 → 평가 재시도
    ↓
GNB 2 · 면접 코칭 (Interview)
    ↓
회사·직군별 면접 상세 화면
    │
    ├── 면접 기록 (전체)
    │      └── 전체 회차 질문·답변 확인
    │
    ├── 평가 기록 (회차별)
    │      ├── 모의 결과 확인
    │      ├── 위원별 임원 평가
    │      ├── 답변별 평가 + 퀘스트 확인 (퀘스트는 2차 MVP)
    │      └── 경험 카드 초안 (2차 MVP)
    │
    └── 재도전 (전체)
           ├── 답변별 코칭 확인
           ├── 개선 답변 작성
           └── 재도전 평가 및 개선 점수 확인
```

'GNB 2 · 면접 코칭' 과 회사·직군별 면접 상세 화면의 1차 화면 구성(GNB 도입 여부 · 화면 통합)은 미확정이다 (10.2). 1차는 같은 데이터 관계(회사 → 직군 → 회차)로 기록을 탐색할 수 있으면 된다.

**주요 원칙**

- 5문항 답변 종료 후 질문·답변 데이터를 해당 회차에 저장한다.
- 사용자가 [평가 받기]를 선택하면 AI 평가를 요청한다.
- AI는 면접 평가를 수행한다. 퀘스트 및 경험 카드 초안 생성은 [2차 MVP]다.
- AI 응답이 검증을 통과하지 못하면 자동으로 1회 다시 요청하고, 그래도 실패하면 평가 완료로 처리하지 않고 오류와 재시도를 안내한다.
- AI 평가 결과는 해당 면접 회차의 평가 기록에 연결한다.
- [평가 확인하기]를 선택하면 해당 회사·직군·회차의 면접 기록 확인 화면으로 이동한다.
- 면접 기록은 전체 회차를 기준으로 확인한다.
- 평가 기록은 회차별 최초 평가 결과를 확인한다.
- 재도전 결과는 최초 평가와 구분하여 누적한다.
- 경험 카드 초안 저장과 퀘스트 수행은 선택 사항이다.
- 면접 평가와 경험 카드 초안 생성은 독립적으로 처리하며, 일부 기능이 실패하더라도 완료된 결과는 확인할 수 있다.

### 6.5 경험 관리부터 시작하는 경우 [2차 MVP]

```text
GNB 3 · 경험 관리 (Experience)
    ↓
프로젝트 및 경험 카드
    ↓
프로젝트/카드 선택 및 생성
    ↓
경험 상세 편집
    ↓
프로젝트 및 경험 카드 저장
    ↓
+ 새 면접 시작 (선택)
    ↓
면접 정보 설정
    ↓
5문항 면접
    ↓
경험 추천 / 비교 확인
    ↓
답변 작성
    ↓
AI 평가
```

**주요 원칙**

- 사용자는 면접을 시작하기 전에 프로젝트와 경험 카드를 등록할 수 있다.
- 경험 관리 기능은 면접 진행 여부와 관계없이 독립적으로 이용할 수 있다.
- 하나의 프로젝트에 여러 경험 카드를 등록할 수 있다.
- 동일한 경험 카드를 여러 면접 질문에서 활용할 수 있다.
- 면접 진행 중에는 등록된 경험 카드를 참고할 수 있다.
- 면접 평가 이후에도 경험 카드를 추가하거나 수정할 수 있다.

### 6.6 경험 카드 초안 검토 및 저장 [2차 MVP]

```text
GNB 2 · 면접 코칭 (Interview)
    ↓
평가 기록 (회차별)
    ↓
경험 카드 초안
    ↓
GNB 3 · 경험 관리 (Experience)
    ↓
경험 상세 편집
    ↓
AI 초안 검토 및 수정
    ↓
저장 여부 결정
    │
    ├── 새 경험 카드로 저장
    │        ↓
    │     저장할 프로젝트 선택
    │        ↓
    │     경험 카드 내용 확인
    │        ↓
    │     저장 확정
    │        ↓
    │     새 경험 카드 생성
    │
    ├── 기존 경험 카드 보완
    │        ↓
    │     보완할 경험 카드 선택
    │        ↓
    │     기존 카드와 AI 초안 비교
    │        ↓
    │     반영할 항목 선택
    │        ↓
    │     변경 내용 확인
    │        ↓
    │     저장 확정
    │        ↓
    │     기존 경험 카드 업데이트
    │
    ├── 저장하지 않기
    │
    └── 나중에 검토
             ↓
       검토 대기 유지
```

**주요 원칙**

- AI는 해당 면접 회차의 전체 최초 답변을 기반으로 경험 카드 초안을 생성한다.
- 사용자는 평가 기록에서 경험 카드 초안을 확인할 수 있다.
- 경험 카드 초안을 선택하면 경험 상세 편집 화면으로 이동한다.
- 사용자는 AI가 제안한 프로젝트 및 경험 분류를 수정할 수 있다.
- 기존 경험 카드를 보완할 경우 변경 내용을 비교한 후 저장한다.
- 사용자 확인 없이 경험 카드를 자동으로 저장하거나 덮어쓰지 않는다.
- 검토하지 않은 초안은 '검토 대기' 상태로 유지한다.
- 경험 카드 저장 여부는 기존 면접 평가 결과에 영향을 주지 않는다.

### 6.7 면접 재도전

**Markdown 복원 후 바로 재도전 (1차 확정)**

```text
Markdown 파일 업로드
        ↓
기존 회사 및 직군 선택
        ↓
기존 면접 회차 선택
        ↓
기존 질문 및 평가 결과 확인
        ↓
보완할 질문 선택
        ↓
재도전
        ↓
답변 제출
        ↓
평가 및 이전 결과 비교
        ↓
필요하면 다시 재도전 (횟수 제한 없음)
```

이 과정에서 새로운 면접 회차를 만들 필요가 없다. 같은 질문에 몇 번이든 다시 재도전할 수 있다.

**재도전 상세 흐름**

```text
GNB 2 · 면접 코칭 (Interview)
    ↓
면접 데이터 목록
    ↓
회사별 데이터 선택
    ↓
직군 선택
    ↓
면접 상세 화면
    ↓
재도전 (전체)
    │
    ├── 전체 답변별 코칭 확인
    │
    └── 전체 답변별 재도전
            ↓
        기존 회차 및 질문 선택
            ↓
        최초 답변 및 평가 확인
            ↓
        개선 답변 작성
            ↓
         현재 답변 독립 평가
            ↓
         재도전 답변 및 평가 결과 저장
            ↓
         선택한 회차·질문의 이전 최고 점수 확인
            ↓
         현재 답변과 기존 최고 점수 답변 비교
            ↓
         평가 항목별 점수 변화 확인
            ↓
         AI 비교 코칭 확인
            ↓
         현재 점수가 더 높은 경우 최고 점수 갱신
            ↓
         다른 회차의 동일 질문 최고 점수 확인 (참고)
            ↓
         재도전 결과 확인
```

**주요 원칙**

- 재도전은 새로운 면접 회차를 생성하지 않는다. 회차 번호도 늘지 않는다.
- 재도전은 기존 면접 회차의 질문·답변에 연결된다 (`round_id` · `question_id`). 재도전 기록마다 고유 ID(`attempt_id`)를 둔다.
- 재도전 횟수 제한은 없다. 횟수 초과 차단이나 남은 횟수 표시를 두지 않는다.
- 재도전 순서는 저장된 재도전 기록을 기준으로 계산한다.
- 사용자는 기존 답변의 코칭 내용을 확인하고 개선 답변을 작성할 수 있다.
- 개선 답변은 최초 답변과 동일한 평가 기준으로 평가한다.
- 최초 답변과 최초 평가 결과는 보존한다.
- 재도전 결과는 개선 이력으로 누적한다.
- 사용자는 최초 답변과 개선 답변을 비교할 수 있다.
- 사용자는 재도전별 평가 점수와 해당 재도전 이전의 최고 점수 대비 변화를 확인할 수 있다.
- 재도전으로 생성된 평가 결과는 평가 기록(회차별)의 최초 평가 점수를 변경하지 않는다.
- 퀘스트 수행이나 경험 카드 저장은 재도전의 필수 조건이 아니다.

### 6.8 취업 관리 [2차 MVP]

```text
GNB 4 · 취업 관리 (Schedule)
    ↓
전체 지원 현황 및 일정
    ↓
회사별 데이터 선택
    ↓
회사 내 직군 확인
    │
    ├── 직군 1개
    │      ↓
    │   해당 직군의 지원 정보 및 일정 관리
    │
    └── 직군 2개 이상
           ↓
        직군별 하위 그룹 선택
           ↓
        해당 직군의 지원 정보 및 일정 관리
```

**주요 원칙**

- 사용자는 전체 지원 현황과 일정을 확인할 수 있다.
- 회사명을 기준으로 지원 정보와 면접 데이터를 자동 그룹화한다.
- 동일 회사에 여러 직군이 등록된 경우 직군별 지원 정보와 일정을 구분한다.
- 지망 태그는 회사 단위로 설정한다.
- 지원 상태와 일정은 회사·직군 조합을 기준으로 관리한다.
- 취업 관리에 등록된 회사 및 직군 정보는 면접 정보 설정에서 참조할 수 있다.
- 취업 관리 데이터는 개별 면접 회차와 구분하여 관리한다.
- 회사별 면접 기록 및 평가 결과는 면접 코칭에서 확인할 수 있다.

### 6.9 공통 사용자 원칙

- 경험 관리와 면접 코칭은 독립적으로 이용할 수 있다. [경험 관리는 2차 MVP]
- 경험 카드 등록은 면접 시작의 필수 조건이 아니다.
- 하나의 면접관 페르소나가 진행하고, 본 질문당 꼬리질문은 최대 1개다. 면접 중에는 코칭 · 평가를 제공하지 않는다.
- 재도전 횟수 제한은 없다.
- 면접 질문·답변 진행 중에는 프로젝트·경험 카드의 조회·비교·선택·참고만 허용한다.
- 경험 카드 생성·수정은 면접 진행 상태와 분리하여 관리한다.
- 경험 카드 생성, 퀘스트 수행, 재도전은 서로 독립적인 선택 행동이다.
- 새로운 면접 회차와 재도전 이력은 구분하여 관리한다.
- 면접 회차는 회사(또는 '기타')·직군을 기준으로 통합 관리한다.
- 공통 면접과 분야별 면접은 별도의 회차 번호를 부여하지 않는다.
- 최초 답변과 평가 결과는 이후의 재도전이나 경험 카드 수정으로 덮어쓰지 않는다.
- 재도전 결과는 별도 이력으로 누적하고 개선 점수를 확인할 수 있다.
- 암기용 답변 관리 및 원본 답변 삭제 기능은 이번 MVP에서 제공하지 않는다. (기존 프로토타입의 암기 · 사전 탐색 · 마지막 질문 기능의 1차 유지 여부는 미확정, 10.2)
- Markdown 복원은 기존 데이터를 불러오는 기능이며, 새로운 면접 회차를 생성하지 않는다.
- 서비스 내부에서는 4개의 GNB를 통해 주요 기능에 접근할 수 있다. (1차 GNB 도입 여부는 미확정, 10.2)
- [+ 새 면접 시작]과 [데이터 저장하기]는 공통 기능으로 제공한다.
- 정보구조와 상세 화면 이동 및 데이터 연동 관계는 `IA_UserFlow.md`에서 정의한다.

## 7. MVP 범위 및 우선순위

> 1차 · 2차 구분은 0.1 을 따른다. 이 장의 항목 중 2차 범위에는 [2차 MVP] 를 표시한다.

### 7.1 기존 기능 유지 및 구조 변경

기존 프로토타입에서 구현된 기능을 우선 분석하고, 유지 가능한 구조를 활용한다 (C안).

**기존 기능 유지 대상**

- 사용자 정의 태그 생성 및 분류
- 사용자 정의 그룹 생성 및 그룹화
- 5문항 면접 진행
- 면접 답변 평가 및 결과 확인
- 퀘스트 (기존 '역전의 실마리' — 1차는 실마리 유지, 퀘스트 전환은 미확정)
- 면접 재도전 및 평가 비교 (재도전 횟수 제한은 없앤다)
- 기존 면접 기록 Markdown 내보내기 및 복원 (1차: v2 통합 저장 + v1 읽기 호환)
- 사전 준비된 질문 목록 기반 면접 출제
- 질문 출제 방식 선택 (새로운 문제만 / 섞어서 / 똑같은 질문)

**기존 기능의 구조 변경**

- 기존 '빠른 피드백' 면접 방식을 없애고 하나의 면접관 페르소나로 통합한다. (1차)
- 기존 '재도전 질문당 최대 3회' 제한을 삭제한다. (1차)
- 회차 번호를 업로드한 리포트 1개 기준이 아니라 회사 · 직군 기준으로 누적한다. (1차)
- 기존 사용자 정의 그룹화 구조를 회사명 기반 자동 그룹화 구조로 변경한다. [2차 MVP — 1차는 기존 그룹 · 태그 유지]
- 동일한 회사명의 데이터는 하나의 회사 그룹으로 통합한다. (회사 식별 · 회차 연결은 1차)
- 동일 회사 내 직군이 다른 경우 직군별 하위 그룹을 생성한다. (회사 · 직군 단위 회차 관리는 1차)
- 기존 태그 기능을 활용하여 회사별 지망 태그를 설정할 수 있도록 한다. [2차 MVP]
- 지망 태그는 1지망, 2지망 등 사용자가 직접 생성·분류할 수 있다. [2차 MVP]
- 새로운 면접은 [+ 새 면접 시작]에서 진행한다.
- 면접 회차는 회사(또는 '기타')·직군별로 독립적으로 관리하되, 동일 회사·직군 내 공통 면접과 분야별 면접의 회차는 통합한다.
- 공통 면접과 분야별 면접은 별도의 회차 번호를 부여하지 않는다.
- 새로운 면접 회차는 기존 회차의 질문·답변·평가 결과를 보존한다.
- 재도전은 새로운 면접 회차를 생성하지 않고 기존 답변에 개선 이력을 추가한다.
- 재도전 결과는 최초 평가 결과와 구분하여 저장한다.
- 기존 Markdown 파일을 복원하여 저장된 데이터를 이어서 이용할 수 있다.
- 기존 면접 기록의 직군명을 수정하는 기능은 제공하지 않는다.

기존 기능의 구체적인 변경·제거 여부는 코드 분석과 기획 검토 후 확정한다.

### 7.2 이번 MVP의 신규 핵심 기능

**우선 구현 대상**

아래 1 · 2 · 5 는 [2차 MVP], 3 · 4 는 1차 MVP 범위다. 5 중 회사 · 직군 식별과 회차 연결은 1차에 포함한다.

- 경험·면접 통합 Markdown 내보내기 [2차 MVP]

**5. 회사별 데이터 및 취업 관리** [2차 MVP — 회사 · 직군 식별과 회차 연결은 1차]

- 취업 관리 데이터를 면접 정보 설정에서 참조

## 8. 데이터 및 AI 처리 원칙

### 8.1 데이터 독립성

다음 데이터는 서로 구분하여 관리한다.

- 회사 및 직군 정보
- 회사별 지망 태그
- 회사·직군별 지원 정보 및 일정
- 면접 회차
- 면접 유형 (공통 면접 / 분야별 면접)
- 면접 질문 및 최초 답변
- 최초 면접 평가 결과
- 재도전 답변 및 평가 이력
- 프로젝트
- 경험 카드
- AI 프로젝트·경험 카드 초안
- 퀘스트

**면접 데이터 관리 원칙**

- 면접 회차는 회사(또는 '기타')·직군을 기준으로 통합 관리한다.
- 공통 면접과 분야별 면접은 회차를 분리하지 않는다.
- 동일한 질문이 여러 회차에 출제되더라도 질문·답변·평가 결과는 회차별로 독립 저장한다.
- 각 회차의 최초 답변과 최초 평가 결과는 보존한다.
- 재도전 답변과 평가 결과는 최초 답변에 연결된 별도 개선 이력으로 저장한다.
- 경험 카드, 면접 답변, 평가 결과, 퀘스트는 서로 연결할 수 있지만 동일한 데이터로 취급하지 않는다.
- 암기용 답변 관리 및 원본 답변 삭제 기능은 이번 MVP에서 구현하지 않는다. (기존 프로토타입 암기 기능의 1차 처리는 미확정, 10.2)
- 회사를 지정하지 않은 면접 기록('기타' 그룹)도 회차 · 질문 · 답변 · 평가 · 재도전을 같은 원칙으로 보존한다.

### 8.2 면접 평가 원칙

- AI 면접 평가의 직접적인 대상은 사용자가 실제 제출한 답변이다.
- 경험 카드의 내용이나 완성도는 평가 점수에 직접 반영하지 않는다.
- 경험 카드에 기록되어 있더라도 실제 답변에 포함되지 않은 내용은 평가 근거로 사용하지 않는다. 면접 시작 전에 입력한 경험 내용도 같다.
- 기존 평가 체계(평가위원 4명 · 답변별 기준 점수 · 위원 평균 의견)를 유지한다.
- AI 응답의 형식 오류, 평가위원 · 평가 항목 누락, 질문 번호 · ID 불일치는 정상 평가로 처리하지 않는다. 자동으로 1회 다시 요청하고, 그래도 실패하면 평가 오류를 안내한다. 0점으로 채우거나 답변을 다른 질문에 연결하지 않는다. 범위를 벗어난 정수 점수는 경계값으로 보정한다.
- 평가 응답 검증 실패가 반복되면 프롬프트와 평가 기준 자체를 점검한다. 자동 재시도는 평가 기준의 문제를 감추는 수단이 아니다.
- 각 면접 회차의 최초 평가 점수와 평가 내용은 해당 회차에 연결하여 보존한다.
- 경험 카드를 수정하거나 새로운 회차를 진행해도 과거 면접 평가 결과는 변경되지 않는다.
- 재도전 시 새로운 답변을 기준으로 별도 평가한다.
- 재도전 결과는 최초 평가를 덮어쓰지 않는다.
- 최초 답변과 모든 재도전 답변에 동일한 평가 기준을 적용한다.
- 각 답변은 이전 답변과 평가 점수에 영향을 받지 않고 독립적으로 평가한다.
- 평가 결과에는 평가 항목별 점수와 판단 근거를 기록한다.
- 재도전 점수는 해당 재도전 이전의 최고 점수를 기준으로 비교한다.
- 최고 점수는 선택한 면접 회차의 해당 질문에 연결된 최초 답변 및 재도전 답변만을 대상으로 산출한다.
- 다른 면접 회차의 동일 질문 답변과 평가 점수는 현재 회차의 최고 점수 산출에 영향을 주지 않는다.
- 다른 회차의 동일 질문 최고 점수는 참고 정보로만 제공한다.
- 재도전 점수가 기존 최고 점수보다 높으면 최고 점수를 갱신한다.
- 점수가 하락하더라도 해당 점수와 평가 결과를 그대로 기록한다.
- 최초 평가와 재도전 평가 결과는 재평가하거나 덮어쓰지 않는다.
- 점수 변화와 실제 답변 내용의 질적 개선을 구분하여 확인할 수 있도록 한다.
- AI 비교 코칭은 독립 평가 완료 후 수행하며 점수 산출에 영향을 주지 않는다.
- 경험 카드가 수정되더라도 과거 면접 답변과 평가 결과는 변경하지 않는다.

### 8.3 경험 추천 원칙

- 경험 추천은 규칙 기반으로 구현한다.
- 질문 유형과 요구 역량, 경험 카드에 등록된 정보를 기준으로 추천한다.
- 경험 추천 적합도와 실제 면접 평가 점수는 구분한다.
- 경험 카드의 참고·선택 여부는 평가 점수와 별도로 기록한다.
- 경험 카드가 없는 사용자도 면접에 참여하고 평가받을 수 있다.

### 8.4 AI 경험 분석 원칙

- AI는 해당 면접 회차의 전체 최초 답변을 기반으로 경험을 추출한다.
- 동일 경험의 중복 여부와 프로젝트별 분류를 검토하여 초안을 제안한다.
- AI가 추출한 경험에는 근거가 된 실제 질문과 답변을 연결한다.
- AI는 사용자 답변에 없는 경험, 역할, 성과, 수치를 생성하지 않는다.
- 정보가 부족한 경우 임의로 보완하지 않고 사용자에게 확인이 필요한 항목으로 표시한다.
- 사용자는 AI가 제안한 프로젝트와 경험 분류를 수정할 수 있다.
- 재도전으로 생성된 답변과 최초 면접 답변은 구분하여 관리한다.
- 재도전 답변을 경험 카드 초안 생성에 추가로 활용할지는 별도 기능 요구사항에서 정의한다.
- 경험의 중복 여부는 프로젝트명만으로 판단하지 않고 실제 사건과 행동의 동일성을 기준으로 판단한다.
- 동일 프로젝트의 서로 다른 사건·행동은 독립적인 경험으로 취급한다.
- 동일한 경험에서 여러 역량이 발견되더라도 경험 카드를 불필요하게 중복 생성하지 않는다.
- 경험의 동일 여부가 불확실한 경우 AI가 임의로 통합하지 않고 사용자 확인을 요청한다.
- 경험 카드의 최종 분류와 통합 여부는 사용자가 결정한다.

### 8.5 사용자 승인 및 저장 원칙

- AI 초안과 정식 프로젝트·경험 카드는 구분하여 관리한다.
- AI 초안의 정식 저장에는 사용자의 명시적인 확인이 필요하다.
- AI는 기존 프로젝트나 경험 카드를 자동으로 덮어쓰지 않는다.
- 기존 경험 카드 보완 시 변경 내용을 비교한 후 저장한다.
- AI 초안의 저장 여부는 기존 면접 답변과 평가 결과에 영향을 주지 않는다.
- 저장하지 않은 AI 초안은 정식 경험 관리 Markdown 내보내기에 포함하지 않는다.
- Markdown 저장 및 복원 시 면접 회차, 최초 평가, 재도전 이력의 관계를 유지한다.

세부 데이터 관계와 상태 정의는 `technical/DATA_MODEL.md`, AI 처리 규칙은 `technical/AI_RULES.md`에서 정의한다.

## 9. 성공 지표 및 검증 계획

### 9.1 검증 목적

MVP 전체(1차 · 2차)에서 경험 관리와 면접 코칭 기능이 사용자의 경험 선택 및 답변 개선 과정에 실질적으로 도움이 되는지 확인한다. 1차 MVP는 면접 코칭과 답변 개선(재도전) 관련 항목을, 2차 MVP는 경험 선택 · AI 경험 카드 초안 · 퀘스트 관련 항목을 검증한다. 목표치는 9.4 에 따라 따로 정한다.

특히 다음 가설을 검증한다.

- 사용자가 질문에 적합한 경험을 선택하는 데 도움을 받는가? [2차 MVP]
- 사용자가 경험 정보의 부족과 답변 전달의 부족을 구분할 수 있는가? [2차 MVP]
- 평가 결과가 구체적인 개선 행동으로 연결되는가? (1차: 재도전 · 2차: 퀘스트)
- AI가 생성한 경험 카드 초안을 사용자가 이해하고 신뢰할 수 있는가? [2차 MVP]

### 9.2 주요 검증 지표

| 검증 항목 | 측정 지표 | 측정 방법 | 단계 |
|---|---|---|---|
| 경험 선택 지원 | 적합한 경험 선택에 대한 사용자 인식 | 사용성 테스트 후 설문 | 2차 |
| 경험 카드 활용 | 면접 답변에서 경험 카드 참고·선택 비율 | 서비스 이용 기록 | 2차 |
| AI 경험 추출 | AI 초안의 경험 분류 정확성 | 원본 답변과 초안 비교 | 2차 |
| AI 초안 활용 | 초안 검토 및 저장 비율 | 초안 상태 기록 | 2차 |
| AI 초안 신뢰 | AI가 추출한 경험의 정확성·신뢰도 평가 | 사용자 설문 | 2차 |
| 개선 행동 유도 | 퀘스트 확인 및 수행 비율 | 서비스 이용 기록 | 2차 |
| 답변 개선 | 재도전 이전 최고 점수 대비 변화 및 평가 항목별 점수 변화 | 동일 평가 기준에 따른 독립 평가 및 최고 점수 비교 | 1차 |
| 답변의 질적 개선 | 기존 최고 점수 답변 대비 구체성·근거·전달력 등의 변화 | AI 비교 코칭 및 사용자 평가 | 1차 |
| 서비스 이해도 | 핵심 과업 완료 여부 | 사용성 테스트 | 1차 · 2차 |

### 9.3 검증 방법

**사용성 테스트**

- 면접부터 시작하는 사용자와 경험 관리부터 시작하는 사용자의 시나리오를 구분한다. (1차는 면접부터 시작하는 시나리오, 경험 관리부터 시작하는 시나리오는 2차)
- 프로젝트·경험 카드 생성, 경험 선택, AI 초안 검토, 저장 등의 주요 과업을 수행하도록 한다. (경험 관련 과업은 2차, 면접 · 평가 · 재도전 · 저장 · 복원 과업은 1차)
- 과업 완료 여부와 사용 중 발생한 혼란 및 오류를 기록한다.

**AI 경험 카드 검증** [2차 MVP]

- 테스트용 면접 답변을 준비한다.
- 실제 답변에 포함된 경험과 AI가 추출한 내용을 비교한다.
- 프로젝트 분류, 동일 경험 통합, 근거 답변 연결, 누락 및 임의 생성 여부를 점검한다.
- 사용자가 AI 초안을 검토·수정하는 과정에서 발생한 문제를 기록한다.

**사용자 인식 조사**

- 경험 선택에 도움이 되었는지 확인한다. [2차 MVP]
- 경험 강화와 전달 강화의 차이를 이해했는지 확인한다. [2차 MVP]
- AI 경험 카드 초안을 신뢰할 수 있었는지 확인한다. [2차 MVP]
- 면접 답변을 개선하는 데 도움이 되었는지 확인한다. (1차)

### 9.4 검증 시 유의사항

- 문제 가설은 실제 사용자 조사로 검증하기 전까지 확정된 사실로 표현하지 않는다.
- 검증 지표의 목표치는 사전 테스트와 팀 검토를 거쳐 설정한다.
- 사용성 테스트 결과와 AI 분석 정확도는 구분하여 해석한다.
- 재도전 점수 변화만으로 서비스의 효과를 단정하지 않는다.
- 실제 사용자 테스트 결과와 모의 데이터 기반 테스트 결과를 구분하여 기록한다.

## 10. 제약사항 및 미결정 사항

### 10.1 개발 제약사항

- 기존 프로토타입을 기반으로 기능을 확장한다.
- 기존 기능의 동작과 데이터 구조를 분석한 후 변경 범위를 확정한다.

- 세부 화면 구조와 데이터 저장 방식은 개발 검토를 거쳐 확정한다.

### 10.3 문서 관리 원칙

- 본 PRD는 서비스의 목적, 범위, 핵심 요구사항 및 검증 기준을 정의한다.
- 사용자 흐름의 상세 화면 전환은 `IA_UserFlow.md`에서 관리한다.
- 화면별 기능 및 완료 기준은 `features/` 문서에서 관리한다.
- 데이터 관계와 저장 구조는 `technical/DATA_MODEL.md`에서 관리한다.
- AI 처리 및 경험 추천 규칙은 `technical/AI_RULES.md`에서 관리한다.
- 기존 프로토타입에서 신규 구조로 전환하는 과정은 `MIGRATION.md`에서 관리한다.
- 기능 요구사항은 `EXP-`, `INT-`, `SCH-`, `HOME-`, `DATA-`, `AI-`, `EXPOR-` ID로 추적한다.
- 기존 기능의 변경·제거 여부는 코드 분석과 팀 검토 후 확정한다.

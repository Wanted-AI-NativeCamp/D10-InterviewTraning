# 역전 취업 코칭 — 문서 안내

> 기준 문서: PRD v2.3  
> 기준일: 2026-11-02  
> 상태: 팀 검토용 초안  
> 개발 기준: 기존 프로토타입 분석 완료 · C안(기존 면접 엔진 유지 + 2차 확장 구조만 부분 개선)

## 서비스 한 줄 소개

별도의 경험 등록 없이 빠르게 면접을 시작하고, AI 평가를 바탕으로 경험과 면접 전략·일정을 체계적으로 관리하며 취업 전략을 개선하는 AI 취업 코칭 서비스.

## 개발 단계 (PRD 0장)

| 단계 | 범위 |
|---|---|
| **1차 MVP — AI 면접 코칭** | 면접 정보 설정 → 공통/분야별 5문항 면접(단일 면접관 · 꼬리질문 최대 1개) → AI 평가 → 결과 확인 → 답변 재도전(횟수 제한 없음) · 회사·직군·회차별 기록 · Markdown v2 통합 저장과 v1·v2 복원 |
| **2차 MVP — 경험 정리 · 취업 전략 관리** | 프로젝트·경험 카드 · AI 경험 카드 초안 · 면접 중 경험 추천·비교·선택 · 경험 강화 퀘스트 · 회사별 전략·지망 태그 · 지원 현황·일정 · 데이터 통합 · 선택 저장 |

아래 내용 중 2차 범위에는 **[2차 MVP]** 를 표시했다. 2차 기능은 삭제가 아니라 향후 범위다. 문서의 정책은 목표 정책이며 현재 코드와의 차이는 `MIGRATION.md` 에 있다.

## 가장 중요한 사용자 흐름

역전 취업 코칭은 **경험 등록 없이 면접부터 시작하거나, 경험을 먼저 정리한 후 면접에 활용할 수 있는 서비스**다.

사용자는 면접 답변을 통해 자신의 경험을 발견하고, AI가 생성한 프로젝트·경험 카드 초안을 검토·수정하여 저장할 수 있다. 필요에 따라 면접 시작 전에 프로젝트와 경험 카드를 직접 작성할 수도 있다.

서비스는 두 가지 시작 경로를 제공하며, 면접을 시작한 이후에는 동일한 공통 흐름을 따른다.

### 1. 면접부터 시작하는 경우

```text
서비스 시작
    │
    ├── [+ 새 면접 시작]
    │     ↓
    │   회사명(선택)·지원 직군·면접 유형 설정
    │     ↓
    │   질문 출제 방식 설정(해당하는 경우)
    │     ↓
    │   새 면접 회차 생성 및 시작
    │     ↓
    │   [면접 공통 흐름]으로 이동
    │
    └── [기존 데이터 Markdown 복원]
          ↓
        Markdown 파일 불러오기
          ↓
        기존 면접·경험·취업 관리 데이터 복원
          ↓
        기존 기록 확인 또는 새 면접 시작(선택)
          │
          └── 새 면접 시작 시 면접 정보 설정으로 이동
```

- 등록된 프로젝트·경험 카드가 없어도 면접을 시작할 수 있다.
- Markdown 복원 자체는 새로운 면접 회차를 생성하지 않는다.
- 복원 후 기존 기록만 확인하거나 새로운 면접을 시작할 수 있다.

### 2. 경험 관리부터 시작하는 경우 [2차 MVP]

```text
경험 관리 진입
    ↓
프로젝트·경험 카드 조회 또는 등록·수정
    │
    ├── 경험 관리 계속 이용
    │
    └── [+ 새 면접 시작](선택)
          ↓
        회사명(선택)·지원 직군·면접 유형 설정
          ↓
        질문 출제 방식 설정(해당하는 경우)
          ↓
        새 면접 회차 생성 및 시작
          ↓
        [면접 공통 흐름]으로 이동
```

- 하나의 프로젝트에 여러 경험 카드를 등록할 수 있다.
- 프로젝트·경험 카드는 면접 진행 여부와 관계없이 관리할 수 있다.
- 사용자는 질문에 적합한 경험을 규칙 기반 추천 또는 직접 선택을 통해 비교할 수 있다.
- 강조하려는 역량에 따라 활용할 경험을 전략적으로 선택할 수 있다.
- 면접 진행 중에는 경험 카드의 조회·비교·선택·참고만 가능하다.
- 면접 진행 중 프로젝트·경험 카드를 새로 등록하거나 수정할 수 없다.

### 3. 면접 공통 흐름

두 시작 경로에서 새 면접을 시작하면 다음 흐름을 공통으로 적용한다.

```text
새 면접 회차 시작
    ↓
질문 확인
    ↓
경험 추천·비교·선택 또는 경험 없이 답변   (경험 추천·비교·선택은 2차 MVP)
    ↓
답변 제출
    ↓
면접관 반응 (필요하면 꼬리질문 1개 → 답변)
    ↓
5문항 답변 완료
    ↓
[평가 받기]
    ↓
AI 면접 평가 및 최초 답변 기반 경험 카드 초안 생성   (초안 생성은 2차 MVP)
    ↓
[평가 확인하기]
    ↓
평가 결과 확인
    │
    ├── 경험 카드 초안 검토·저장(선택 · 2차 MVP)
    │
    ├── 퀘스트 확인·수행(선택 · 2차 MVP, 1차는 '역전의 실마리')
    │
    └── 재도전(선택 · 횟수 제한 없음)
```

#### 면접 진행 방식 (1차 확정)

- 하나의 일관된 면접관 페르소나로 진행한다. 기존 '빠른 피드백' 면접 방식은 1차 목표 구조에서 제거한다.
- 본 질문당 선택적 꼬리질문은 최대 1개다. 실무 근거 검증을 기본으로 하고, 필요할 때 경험 탐색에 쓴다.
- 면접 진행 중에는 답변 개선 코칭이나 평가를 제공하지 않는다. 평가 · 코칭 · 재도전은 면접 완료 후 제공한다.

#### 면접 진행 및 평가 원칙

- AI 면접 평가와 경험 카드 초안 생성은 독립적으로 처리한다. (초안 생성은 2차 MVP)
- 면접 평가가 실패한 경우 평가 완료로 처리하지 않으며 재시도를 안내한다. AI 응답의 형식 오류 · 평가위원 / 항목 누락 · 질문 번호 · ID 불일치도 실패로 보며, 이때는 자동으로 1회 다시 요청한 뒤에도 실패하면 오류를 안내한다. 범위를 벗어난 정수 점수는 실패가 아니며 경계값으로 보정한다.
- 경험 카드 초안 생성에 실패하더라도 정상적으로 완료된 면접 평가 결과는 확인할 수 있다.
- 실패한 기능은 성공한 결과를 유지한 상태에서 개별적으로 재시도할 수 있다.
- 5문항 답변 완료 후 [평가 받기]를 선택하면 AI 평가를 실행한다.
- 평가가 정상적으로 완료된 경우 평가 결과를 제공한다.
- 기존 프로토타입의 평가 결과 화면을 유지한다. 퀘스트 발생 여부·개수·바로가기 버튼과 AI 경험 카드 초안 확인 기능은 [2차 MVP]에서 추가한다.
- 평가 결과 화면에서 경험 카드 생성·수정 기능으로 이동할 수 있다. [2차 MVP]
- 프로젝트·경험 카드의 실제 생성·수정은 경험 관리의 [경험 상세 편집] 화면에서 수행한다. [2차 MVP]
- 경험 카드 생성·수정과 퀘스트 수행은 선택 사항이며, 다음 기능 이용의 필수 조건이 아니다.

### 4. 면접 유형 및 질문 출제

- 첫 회차부터 공통 면접과 분야별 면접을 자유롭게 선택할 수 있다.
- 공통 면접은 공통 질문 5문항으로 구성한다. ('공통 질문'의 정의는 미확정, PRD 10.2)
- 분야별 면접은 공통 질문 2문항과 해당 분야 질문 3문항으로 구성한다.
- 면접 질문은 '새로운 문제만', '섞어서', '똑같은 질문' 방식으로 출제할 수 있다.
- '똑같은 질문'은 이전 회차를 선택하거나 기존 출제 질문에서 무작위로 선정하는 방식으로 구분한다.
- 이전 회차 선택은 현재 면접 유형과 분야가 일치하는 회차만 허용한다.
- 해당 회사·직군의 첫 면접에서는 질문 출제 방식 선택 영역을 표시하지 않는다.
- 각 출제 방식은 필요한 질문과 이전 출제 기록이 존재하는 경우에만 선택할 수 있다.
- 면접 회차는 회사(또는 '기타' 그룹)·직군(직무)별로 누적하며, 공통 면접과 분야별 면접의 회차 번호는 통합 관리한다. 면접 유형은 질문 구성 유형일 뿐 회차를 나누지 않는다.
- 회사 지정은 필수가 아니다. 회사 없이 직군 · 분야만 골라 시작한 면접은 화면에서 '기타' 그룹으로 분류한다.
- 재도전은 기존 회차의 답변 버전으로 관리하며 새로운 면접 회차를 생성하지 않는다.

### 5. 재도전 (1차 확정)

```text
Markdown 파일 업로드
        ↓
기존 회사 및 직군 선택 → 기존 면접 회차 선택
        ↓
기존 질문 및 평가 결과 확인 → 보완할 질문 선택
        ↓
재도전 → 답변 제출 → 평가 및 이전 결과 비교
        ↓
필요하면 다시 재도전
```

- 재도전은 기존 회차에 속한 답변 개선 이력이다. 새 회차를 만들지 않고 회차 번호도 늘지 않는다.
- **재도전 횟수 제한은 없다.** 횟수 초과 차단 · 남은 횟수 표시 · 제한용 카운터를 두지 않는다.
- 원본 답변과 기존 재도전 기록을 유지하고, 새 답변과 평가 결과를 별도 이력으로 누적한다.
- 재도전 기록은 `round_id` · `question_id` 에 연결하고 기록마다 고유 ID(`attempt_id`)를 둔다. 순서는 저장된 기록으로 계산한다.
- 기존 평가 결과는 바꾸지 않는다. 과거 평가의 질문 · 답변 · 평가 결과는 당시 상태를 유지한다.

### 6. 데이터 식별 (1차 확정)

- **회사:** `company_id`(고유 ID) · `company_name`(표시 이름) · `company_key`(앞뒤 공백만 제거한 비교용 키). 키가 정확히 같으면 같은 회사.
- **회사 미지정:** 화면에서 '기타' 그룹. 실제 회사명 '기타'와 구분하고 회사 데이터로 취급하지 않는다. 내부 식별 방식과 미지정 기록의 회사 연결은 미확정.
- **회차:** `round_id`(고유 ID) · `round_number`(회사(또는 '기타')·직군별 누적 표시 번호, 공통·분야별 면접 공유, 재도전으로 늘지 않음).
- **질문:** `Q0001` 형식의 영구 ID. 바꾸거나 다시 쓰지 않으며, 과거 기록에는 당시 질문 문구를 함께 보존한다. 현재 질문 은행에 없는 과거 질문도 원문 · 답변 · 평가 · 재도전 이력을 보존하고 재도전할 수 있다 (ID 매핑 실패 시 처리 방식은 미확정).

## 면접 답변 기반 경험 카드 생성 [2차 MVP]

면접 완료 후 AI는 해당 회차의 **전체 최초 답변 5개**를 분석하여 프로젝트·경험 카드 초안을 생성한다.

AI 평가와 경험 카드 초안 생성은 독립적인 처리 과정이며, 한 기능의 실패가 다른 기능의 정상 결과를 변경하거나 차단하지 않는다.

### 1. 경험 카드 초안 검토 흐름

```text
면접 회차의 최초 답변 5개 제출 완료
    ↓
[평가 받기]
    ↓
AI 면접 평가 / 경험 카드 초안 생성
    ↓
[평가 확인하기]
    ↓
평가 결과 확인
    ↓
[이번 회차의 경험 카드 초안 확인하기]
    ↓
프로젝트별 경험 카드 초안 목록 확인
    ↓
검토할 초안 선택
    ↓
경험 관리 → [경험 상세 편집]
    ↓
사용자 검토·수정
    │
    ├── 새 경험 카드로 저장
    ├── 기존 경험 카드 보완
    └── 저장하지 않기
          ↓
다른 초안 검토 또는 평가 기록으로 돌아가기
```

### 2. AI 경험 추출 원칙

- AI는 해당 면접 회차의 전체 최초 답변을 한 번에 분석한다.
- AI는 프로젝트 초안과 해당 프로젝트에 속한 경험 카드 초안을 함께 생성한다.
- 동일한 프로젝트에서 발생한 서로 다른 경험은 별도의 카드 초안으로 구분한다.
- 여러 답변에서 동일한 경험이 등장한 경우 하나의 카드 초안으로 묶어 제안할 수 있다.
- 각 초안에는 근거가 된 면접 질문과 실제 답변을 연결하고, 경험을 추출한 답변 부분을 하이라이트하여 표시한다.
- AI가 제안한 프로젝트와 경험의 분류는 사용자가 수정할 수 있다.
- 프로젝트를 식별할 수 없는 경험은 '프로젝트 미지정'으로 분류하며, 정식 저장 시 프로젝트 연결 여부는 데이터 모델에서 정의한다.
- 경험은 확인되지만 일부 정보가 부족한 경우 빈칸 또는 '추가 작성 필요'로 표시한다.
- 구체적인 경험 자체를 식별할 수 없는 답변은 '경험 추출 어려움 - 보완 필요'로 분류하며, 임의로 경험 카드 초안을 생성하지 않는다.
- AI는 답변에 없는 경험, 역할, 성과, 수치를 임의로 생성하지 않는다.

### 3. 예외 처리

**경험을 추출할 수 없는 경우**

AI 분석은 정상적으로 완료됐지만 추출할 경험이 없다면 다음 안내를 제공한다.

> 생성된 경험 카드가 없습니다. 직접 경험 카드를 추가하고 관리해 보세요.

[경험 관리로 이동] 버튼을 제공한다.

**기술적 오류가 발생한 경우**

- 경험 카드 초안 생성에 실패하면 [다시 시도] 버튼을 제공한다.
- 경험 카드 초안이 생성되지 않아도 정상적으로 완료된 면접 평가 결과는 유지한다.
- 실패한 기능만 개별적으로 재시도할 수 있다.

### 4. AI 초안 상태

| 상태 | 정의 |
|---|---|
| 검토 대기 | AI가 생성했지만 사용자가 저장 여부를 결정하지 않은 초안 |
| 저장 완료 | 사용자가 새 경험 카드로 저장하거나 기존 경험 카드 보완을 완료한 초안 |
| 저장하지 않음 | 사용자가 해당 초안을 저장하지 않기로 선택한 상태 |

#### 저장 및 수정 원칙

- AI가 생성한 경험 카드 초안은 최초 '검토 대기' 상태로 관리한다.
- 프로젝트 초안은 관련 경험 카드와 함께 검토하며, 사용자가 확인한 경우에만 정식 프로젝트로 저장한다.
- 사용자는 각 초안을 개별적으로 검토하고 저장 여부를 결정할 수 있다.
- 일부 초안만 저장하더라도 나머지 초안은 기존 상태를 유지한다.
- 저장 여부를 결정하지 않은 초안은 '검토 대기' 상태로 유지하며 이후 다시 확인할 수 있다.
- AI 초안은 사용자가 저장하기 전까지 정식 프로젝트·경험 카드로 등록하지 않는다.
- AI가 생성한 프로젝트 초안은 사용자가 검토·수정한 후 저장하거나 기존 프로젝트와 연결할 수 있다.
- 기존 경험 카드를 보완할 때는 사용자가 변경 내용을 비교·확인한 후 저장한다.
- AI는 사용자의 확인 없이 정식 프로젝트·경험 카드를 등록·수정·덮어쓰지 않는다.
- 경험 카드 저장 여부와 관계없이 기존 면접 답변과 평가 결과는 변경되지 않는다.

## 퀘스트 [2차 MVP]

> 1차는 기존 '역전의 실마리'를 유지한다. 1차에서 '퀘스트(전달 강화)'로 전환할지는 미확정이다 (PRD 10.2).

퀘스트는 면접 평가 결과를 바탕으로 사용자의 경험 또는 답변 전달 방식을 개선하도록 돕는 선택적 활동이다.

### 퀘스트 유형

| 유형 | 목적 |
|---|---|
| **경험 강화** | 실제 경험의 상황, 행동, 판단 근거, 결과 등을 경험 카드에 작성하거나 보완한다. |
| **전달 강화** | 면접 답변에서 자신의 경험과 역량을 구체적이고 설득력 있게 설명하도록 개선한다. |

- 평가 결과에 따라 필요한 유형의 퀘스트를 제공한다.
- 두 유형을 반드시 모두 수행할 필요는 없다.
- 경험 카드 생성과 퀘스트 수행은 서로 구분한다.
- 퀘스트를 수행하지 않더라도 면접 답변을 바탕으로 경험 카드를 만들 수 있다.
- 퀘스트는 경험 카드 및 면접 답변과 독립된 데이터로 관리한다.

## Markdown 저장 및 불러오기

기존에는 면접을 완료해야 Markdown 파일을 저장할 수 있었고, 파일 하나에 회차 하나(v1)를 담았다.

### 0. 1차 MVP 저장 · 복원 (확정)

- 전체 기록을 **하나의 Markdown v2 파일**로 저장한다. 여러 회사 · 직군 · 회차를 함께 담는다.
- 사람이 읽는 본문과 복원용 데이터(`interview-data` 태그 · `version: 2`)를 함께 저장한다.
- 기존 v1 파일을 읽을 수 있다. 지원하지 않는 버전은 안내하고 안전하게 거부한다.
- 기존 파일을 자동으로 덮어쓰지 않는다. 같은 기록을 다시 불러와도 중복 생성 · 자동 덮어쓰기가 없다.
- 원본 답변 · 재도전 기록 · 과거 평가는 당시 상태로 보존한다.
- 과거 파일에 현재 질문 은행에 없는 질문이 있어도 원문 · 답변 · 평가 · 재도전 이력을 보존하고, 그 질문에 재도전할 수 있다. 다른 질문에 임의로 연결하지 않는다.

### 선택 저장 [2차 MVP — 방향만 확정]

선택 저장은 향후 확장 방향으로 유지한다. 저장 단위 · 화면 구성 · 선택 방식 · 제외 방식 · 저장 전 확인 절차 · 삭제와의 관계는 **미확정**이다.

아래 1 · 2 · 4 는 경험 관리 기능과 함께 [2차 MVP]에서 확정한다. 3 은 1차의 v2 통합 저장이 담는다.

### 1. 경험 관리만 내보내기

- 프로젝트 및 저장 완료된 경험 카드
- 경험 카드의 상태와 역량 태그
- 연결된 퀘스트(선택)
- 면접 진행 여부와 관계없이 저장 가능

### 2. 경험 + 면접 통합 내보내기

- 프로젝트 및 저장 완료된 경험 카드
- 지원 회사 및 직군, 분야 정보
- 회사·직군별 전체 면접 회차와 질문
- 최초 답변 및 평가 결과
- 재도전 답변과 평가 이력
- 경험 강화·전달 강화 유형의 퀘스트
- 진행 중인 면접도 저장 가능하며 미완료 항목을 명시

### 3. 면접 기록만 내보내기

- 1차의 v2 통합 저장이 이 범위를 담는다: 회사 · 직군 · 면접 회차, 질문, 답변, 평가 결과, 재도전 이력
- 기존 v1 면접 리포트는 읽기 호환만 유지한다

### 4. AI 경험 카드 초안과 내보내기

- '검토 대기' 상태의 AI 초안은 정식 경험 관리 Markdown 내보내기에 포함하지 않는다.
- 경험 + 면접 통합 내보내기에는 '검토 대기' 초안의 내용과 처리 상태를 포함한다.
- '저장하지 않음' 상태의 AI 초안은 통합 내보내기에 처리 상태만 기록하며, 초안 내용은 포함하지 않는다.
- 사용자가 검토·저장한 프로젝트와 경험 카드는 정식 경험 관리 데이터로 내보낸다.
- Markdown 복원 시 AI 초안의 처리 상태를 유지한다.
- 복원된 '검토 대기' 초안은 이어서 검토할 수 있다.
- 실제 저장 형식과 복구 구현 방식은 데이터 구조 분석 후 확정한다.

### 5. Markdown 불러오기

- 사용자는 [기존 데이터 Markdown 복원]을 통해 저장된 데이터를 불러올 수 있다.
- 복원된 데이터는 기존 면접 회차, 질문·답변, 평가 결과 및 재도전 이력을 유지한다.
- 복원 파일에 포함된 경험 카드와 취업 관리 정보도 함께 복구한다. [2차 MVP]
- Markdown 복원 자체는 새로운 면접 회차를 생성하지 않는다.
- 사용자는 복원된 데이터를 기반으로 기존 기록을 확인하거나, 기존 회차에서 바로 재도전하거나, 새로운 면접을 시작할 수 있다.
- 기존 v1 파일은 읽기 호환을 유지한다. 지원 · 부분 복원 · 거부 형식은 `MIGRATION.md` 를 따른다.
- 진행 중이던 면접의 질문 단위 재개 방식은 미확정이다 (PRD 10.2).

### 6. 데이터 보존 원칙

- Markdown 저장은 현재 작업 데이터를 백업하기 위한 수동 저장 방식이다.
- 프로젝트·경험 카드·면접 기록·취업 관리 데이터의 변경 사항은 현재 작업 데이터에 반영한다.
- 브라우저 또는 작업 세션 종료 시 백업하지 않은 데이터는 소실될 수 있다.
- 사용자는 변경된 데이터를 보존하기 위해 Markdown 파일을 다시 다운로드해야 한다.
- Markdown 복원 시 백업 파일에 포함된 데이터를 기준으로 작업을 이어서 진행한다.
- Markdown 내보내기는 파일 다운로드이며, 서비스 내부 저장이나 자동저장과 구분한다.

세부 데이터 구조와 저장 형식은 `technical/DATA_MODEL.md`를 참조한다.

## 면접 답변 평가 원칙

- AI 면접 평가의 직접적인 대상은 사용자가 제출한 면접 답변이다.
- 기존 평가 체계(평가위원 4명 · 답변별 기준 점수 · 위원 평균 의견)를 유지한다.
- 프로젝트·경험 카드의 내용이나 완성도, 면접 전에 입력한 경험 내용은 면접 평가 점수에 직접 반영하지 않는다.
- AI 응답 형식 오류 · 필수 평가 항목 누락 · 질문 번호 · ID 불일치는 정상 평가로 처리하지 않는다. 자동으로 1회 다시 요청하고, 그래도 실패하면 평가 오류를 안내한다. 0점으로 채우거나 다른 질문에 연결하지 않는다. 범위를 벗어난 정수 점수는 경계값으로 보정한다.
- 프로젝트·경험 카드는 답변을 준비하고 작성할 때 참고하는 자료로 활용한다.
- 프로젝트·경험 카드에 기록되어 있더라도 실제 답변에 포함되지 않은 내용은 평가 근거로 사용하지 않는다.
- 프로젝트·경험 카드를 수정해도 기존 면접 답변의 평가 점수는 변경되지 않는다.
- 사용자가 답변을 수정하여 재도전하면 새로운 답변을 기준으로 재평가된 점수를 확인할 수 있다.
- 기존 평가 결과는 보존하여 재도전 전후의 변화를 비교할 수 있도록 한다.

## 작업 규칙

- 기능 요구사항은 `EXP-`, `INT-`, `SCH-`, `HOME-`, `DATA-`, `AI-`, `EXPOR-` ID로 추적한다.
- 1차 MVP와 2차 MVP를 구분한다. 2차 범위는 [2차 MVP] 로 표시하고 삭제하지 않는다.
- 면접은 하나의 면접관 페르소나로 진행하고, 본 질문당 꼬리질문은 최대 1개이며, 면접 중에는 코칭 · 평가를 제공하지 않는다.
- 재도전 횟수 제한은 없다. 재도전은 기존 회차의 개선 이력이다.
- **경험 카드 ≠ 활용 답변 ≠ 퀘스트:** 각각 독립된 데이터로 관리한다.
- **AI 경험 카드 초안 ≠ 저장 완료된 경험 카드:** 사용자의 명시적인 저장 전에는 정식 경험 카드로 등록하지 않는다.
- 경험 추천 적합도와 실제 면접 답변 평가 점수는 구분한다.
- 경험 참고 여부는 평가 점수와 별도로 기록한다.
- 경험 카드 수정 시 과거 면접 평가와 당시 경험 정보 스냅샷은 변경하지 않는다.
- 경험 추천은 규칙 기반으로 구현하며, AI는 답변 분석·평가 및 경험 카드 초안 생성에 활용한다.
- AI는 사용자 답변에 없는 경험, 역할, 성과, 수치를 임의로 생성하지 않는다.
- AI 초안은 사용자가 검토·수정한 후 저장한다.
- 기존 경험 카드의 자동 덮어쓰기는 허용하지 않는다.
- 각 기능 문서의 완료 기준을 구현 및 QA 기준으로 사용한다.
- 기존 기능의 변경·제거 여부는 코드 분석과 기획 검토 후 확정한다.

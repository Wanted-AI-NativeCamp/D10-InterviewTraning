# 02. 면접 코칭

> 기준: PRD v2.3 (0장 · 5.1 · 6.1~6.4 · 6.7)  
> 1차 MVP의 핵심 명세다. 경험 카드 관련 항목은 **[2차 MVP]** 로 표시하며 삭제하지 않는다.  
> 이 문서의 정책은 목표 정책이다. 현재 코드와의 차이는 `../MIGRATION.md` 를 본다.

## 목적

면접을 빠르게 시작해 5문항 모의면접을 진행하고, 면접이 끝난 뒤 AI 평가 · 답변 개선 코칭 · 재도전으로 답변을 개선한다.
(2차 MVP에서는 질문에 맞는 경험을 **답변 전에 비교·선택**하는 기능을 더한다.)

## 화면 레이아웃(데스크톱)

-   메인: 면접관 질문, 현재 문항, 답변 입력, 제출.
-   오른쪽 접이식 패널: 경험 추천 목록, 2개 비교, 경험 상세 조회. [2차 MVP]
-   평가: 위원별 평가, 질문별 점수·근거, 답변 개선 코칭, 재도전 진입. (퀘스트 · 선택 경험과 당시 버전은 2차 MVP)
-   1차 화면 구성 (확정): GNB 홈 · 면접 코칭. 면접 코칭 → 면접 데이터 목록 → 회사별 데이터 선택 → 면접 상세 화면의 LNB 3개(면접 기록 (전체) · 평가 기록 (회차별) · 재도전 (전체)). `[평가 확인하기]` 는 그 회사 · 직군 · 회차의 면접 기록 확인 화면으로 간다 (`../IA_UserFlow.md`).

## 면접 진행 (1차 확정)

-   하나의 일관된 면접관 페르소나로 진행한다. 기존 '빠른 피드백' 면접 방식은 1차 목표 구조에서 제거한다.
-   본 질문당 선택적 꼬리질문은 최대 1개다. AI가 더 묻자고 해도 코드가 한도를 지킨다.
-   꼬리질문은 **실무 근거 검증**(답변의 근거 · 구체성 확인)을 기본으로 하고, 필요할 때 **경험 탐색**(답변에 드러나지 않은 경험 발굴)에 쓴다.
-   면접 진행 중에는 답변 개선 코칭이나 평가를 제공하지 않는다. 면접관의 반응은 다음 진행을 위한 짧은 반응에 그친다.
-   평가 · 답변 개선 코칭 · 재도전은 5문항을 마친 뒤 제공한다.
-   경험 카드나 사전 경험 등록 없이 면접을 시작할 수 있다. 기존 '내 경험' 은 선택 입력으로 유지한다 (글자 수 필수 조건 없음 · 면접관 질문 개인화에만 참고 · 평가 근거로 쓰지 않음).
-   직군마다 대표 면접관 1명을 자동 배정하고 사용자가 고르지 않는다 (디자인: 디자인 팀장). 평가위원 4명은 면접이 끝난 뒤 평가하는 별도 역할이다.

## 회사 지정 · 일반 면접 (INT-02, 1차)

-   회사 등록 · 선택은 필수가 아니다. 직무(직군)와 분야만 골라 면접을 시작할 수 있다 (일반 면접).
-   회사를 지정하면 그 회사 그룹에, 지정하지 않으면 화면의 **'기타'** 그룹에 기록한다. '기타' 그룹에서도 회차 · 질문 · 답변 · 평가 · 재도전 기록을 유지한다.
-   화면의 '기타'는 회사 미지정 상태이며, 실제 회사명이 '기타'인 회사와 구분한다.
-   취업 관리에 등록한 회사 · 직군을 면접 설정에서 고르는 기능은 [2차 MVP]다 (PRD 5.5).
-   '기타' 그룹의 내부 식별 방식, 미지정 기록을 나중에 특정 회사로 옮기거나 연결하는 기능은 미확정이다.

## 질문 구성 · 출제 (1차)

-   총 5개 기본 질문. 공통 면접은 공통 질문 5문항, 분야별 면접은 공통 2문항 + 분야 3문항.
-   첫 회차부터 공통 · 분야별 면접을 자유롭게 고를 수 있다.
-   출제 방식 3종과 선택 가능 조건은 PRD 5.1 '질문 출제 방식'을 따른다. 첫 회사·직군 회차에서는 출제 방식 선택 영역을 표시하지 않는다.
-   질문은 영구 질문 ID(`Q0001` 형식)로 식별하고, 회차에는 당시 질문 문구를 함께 저장한다.
-   '공통 질문'의 정의(질문 은행의 분야 '공통' 질문으로 볼지)는 미확정이다.

## 평가 (1차)

-   평가 대상은 실제로 제출한 답변이다. 경험 카드 내용이나 면접 전에 입력한 경험 내용은 평가 근거로 쓰지 않는다.
-   기존 평가 체계를 유지한다: 평가위원 4명의 위원별 평가(점수 · 좋은 점 · 뽑지 말아야 할 이유), 판단이 갈린 곳 · 모두 같은 판단, 답변별 기준 점수.
-   점수 합계 · 평균은 코드가 계산한다. 점수 범위와 계산 방식은 `../technical/AI_RULES.md` 3장을 따른다.
-   질문별 결과(답변별 기준 점수 · 약한 점 · 다듬은 답 · 확인할 사실)와 최종 결과(종합 점수 · 위원 평균 · 위원별 평가 · 모의 결과 판정 · 다음에 고칠 것)를 제공하고, 리포트(Markdown)에 남긴다.
-   AI 평가 응답은 저장 전에 검증한다. 형식 오류, 평가위원 · 평가 항목 누락, 질문 번호 · ID 불일치가 있으면 자동으로 1회 다시 요청하고, 그래도 실패하면 평가 오류를 안내한다 (`../technical/AI_RULES.md` 4장).
-   검증에 실패한 결과는 정상 평가로 저장하지 않는다. 누락된 평가위원을 0점으로 채우거나, 답변을 다른 질문에 연결하지 않는다.
-   검증을 통과한 응답에서 범위(위원 0~10 · 기준 0~5)를 벗어난 정수 점수는 경계값으로 보정하고, 합계 · 평균은 보정한 점수로 코드가 계산한다.
-   AI 실패 시 답변은 먼저 보존하고 평가 대기로 처리한다.
-   평가 결과는 당시 질문 · 답변과 연결해 보존한다.

## 재도전 (1차)

-   재도전은 기존 회차에 속한 답변 개선 이력이다. 새 회차를 만들지 않고 회차 번호도 늘지 않는다.
-   **횟수 제한이 없다.** 횟수 초과 차단 · 남은 횟수 표시 · 제한용 카운터를 두지 않는다.
-   Markdown 복원 후 회사 → 직군 → 회차 → 질문을 골라 바로 재도전할 수 있다 (PRD 6.7).
-   재도전 기록은 `round_id` · `question_id` 에 연결하고 기록마다 `attempt_id` 를 둔다. 순서는 기록으로 계산한다.
-   재도전 답변은 제출 시점의 답변으로 평가하고, 이전 답변 · 평가와 비교해 보여 준다. 비교 기준은 같은 회차 · 질문의 재도전 이전 최고 점수다 (PRD 8.2).
-   원본 답변 · 기존 재도전 기록 · 기존 평가는 바꾸지 않는다.
-   현재 질문 은행에 없는 과거 질문(복원한 Markdown 기록)도 당시 질문 원문을 기준으로 재도전할 수 있다. 과거 평가는 다시 계산하지 않고, 다른 질문에 임의로 연결하지 않는다 (PRD 0.5).

## 회차 기록 (1차)

-   회사(`company_id` · `company_name` · `company_key`) 또는 '기타' 그룹 → 직무(직군) → 회차(`round_id` · `round_number`) 순서로 기록을 찾는다.
-   같은 회사는 앞뒤 공백만 제거한 회사명이 정확히 같은지로 판단한다.
-   회차 번호는 회사(또는 '기타') · 직무별로 누적하고 공통 · 분야별 면접이 같은 번호 체계를 쓴다. 면접 유형은 질문 구성 유형일 뿐 회차를 나누지 않는다 (예시: PRD 0.6).

## 활용 답변 [2차 MVP]

-   질문별 활용 답변 저장(INT-10): 경험 카드를 활용해 작성한 답변을 질문 · 경험과 연결해 남긴다 (`../technical/DATA_MODEL.md` 의 `InterviewAnswer`).
-   용어 구분: **원본 답변**은 회차의 최초 제출 답변, **재도전 답변**은 같은 회차 · 질문의 개선 이력(`attempt_id`), **활용 답변**은 2차의 경험 카드 활용 관점에서 질문 · 경험과 연결된 답변이다. 활용 답변의 구체적인 저장 방식은 2차에서 확정한다.

## 경험 추천·비교 [2차 MVP]

질문은 미리 분류된 `question_type`과 `required_competencies`를 사용한다.
자동 추천: 적합도 높은 경험 2개를 비교 후보로 설정. 직접 선택: 전체 경험
리스트에서 원하는 2개를 지정. 비교 항목: 1. 질문 유형
적합도(높음/보통/낮음/정보 부족) 2. 강조할 역량 3. 실제 행동·판단
근거·결과 기록 상태 4. 경험 강화·전달 강화 퀘스트 상태 5. **기존 활용
답변 평가가 있을 때만** 해당 점수·조건 표시

**경험 적합도 ≠ 답변 평가 점수.** 기존 평가 없는 경험도 비교 가능.
규칙은 `technical/AI_RULES.md`.

## 경험 참고 설정 [2차 MVP]

-   `reference_used=true/false`를 질문별 답변에 저장.
-   면접 시작 시 기본값 선택 가능; 질문별 변경 허용.
-   미참고 시 카드 내용 숨김. 경험 비교는 답변 전 단계에서 허용하되,
    '미참고'의 의미를 **답변 작성 중 카드 내용을 열람하지 않음**으로
    명확히 정의.
-   참고 여부는 점수 산식에 넣지 않음.

## 면접 중 경험 카드 [2차 MVP]

PRD 5.3 · 6.9 에 따라 면접 질문 · 답변 진행 중에는 경험 카드를 **조회 · 비교 · 선택 · 참고만** 하며 등록하거나 수정하지 않는다. (v2.2 의 '사이드 패널에서 경험 추가 · 수정' 요구는 PRD 와 충돌해 삭제했다.)

-   입력 중 답변 및 질문 진행 상태를 유지한다.
-   제출 시 실제 참조한 경험 버전을 답변에 고정한다.
-   이전 완료 평가는 바꾸지 않는다.

## Markdown 저장 · 복원

-   1차: 전체 기록(여러 회사 · 직군 · 회차)을 Markdown v2 파일 하나로 저장한다 (`interview-data` · `version: 2`). 기존 v1 파일을 읽을 수 있고, 지원하지 않는 버전은 안내 후 거부한다. 기존 파일을 자동으로 덮어쓰지 않는다.
-   `EXPOR-02`: 경험+면접 통합 내보내기. [2차 MVP] 기존 요구사항 '세션 진행 중에도 가능'은 조건부로 보존한다 — 진행 중 면접의 저장 · 재개 방식이 확정되면 적용한다.
-   `EXPOR-03`: 면접 기록만 내보내기는 1차 v2 통합 저장이 담는다.
-   진행 중인 면접(평가 전)의 저장 · 재개 방식은 미확정이다. 확정되면 v2.2 의 원칙(미응답 · 미평가 문항은 상태 표시, 작성 중인 미제출 답변은 기본 제외하고 포함 여부를 사용자에게 확인)을 기준으로 검토한다.
-   선택 저장은 2차 방향만 확정했고 UX는 미확정이다.

## 완료 기준

**1차 MVP**

-   경험 카드 없이 면접을 시작해 5문항을 마칠 수 있다.
-   회사를 지정하지 않고 면접을 시작할 수 있고, 그 기록이 '기타' 그룹에 보존된다.
-   평가 응답 검증에 실패하면 자동으로 1회 다시 요청하고, 그래도 실패하면 평가 완료로 표시되지 않는다.
-   첫 회차부터 공통 · 분야별 면접을 고를 수 있다.
-   본 질문당 꼬리질문이 1개를 넘지 않고, 면접 중 코칭 · 평가가 나오지 않는다.
-   평가 응답에 위원 · 항목 누락이나 번호 불일치가 있으면 평가 완료로 표시되지 않는다.
-   같은 질문에 횟수 제한 없이 재도전할 수 있고, 원본 답변 · 기존 평가가 바뀌지 않는다.
-   Markdown 복원 후 새 회차 없이 기존 회차에서 재도전할 수 있다.
-   여러 회사 · 직군 · 회차를 v2 파일 하나로 저장하고 다시 불러올 수 있으며, 기존 v1 파일도 불러올 수 있다.

**2차 MVP**

-   추천된 경험 2개 또는 수동 선택한 경험 2개 비교 가능.
-   선택 경험으로 답변 작성·제출 가능.
-   참고 여부가 별도 기록되고 평가 점수에 영향 없음.
-   카드 수정 후 이전 평가가 그대로 유지됨.
-   면접 도중 통합 Markdown 다운로드 가능. (조건부: 진행 중 면접의 저장 · 재개 방식이 확정되면)

# 03. 경험 관리 [2차 MVP]

> 기준: PRD v2.3 (5.2 · 5.3 · 6.5 · 6.6). 이 문서 전체가 **2차 MVP** 범위다. 1차에서는 구현하지 않으며, 1차 데이터 구조(회차 · 질문 ID · 최초 답변 · 메시지 확장 정보)는 이 기능의 연결을 막지 않도록 설계한다 (`../technical/DATA_MODEL.md`).  
> AI 경험 카드 초안의 생성 · 검토 · 상태(검토 대기 / 저장 완료 / 저장하지 않음)는 PRD 5.2 를 따른다.

## 목적

프로젝트별로 여러 경험을 기록하고, 질문에 활용 가능한 자산으로 관리한다.

## 핵심 기능

  ID       요구사항                                       우선순위
  -------- ---------------------------------------------- ----------
  EXP-01   프로젝트 생성·조회·수정·삭제                   P0
  EXP-02   프로젝트별 경험 카드 생성·조회·수정·삭제       P0
  EXP-03   경험 카드 최소 입력으로 임시저장               P0
  EXP-04   경험 상태·역량 태그·활용 이력 표시             P0
  EXP-05   연결된 강화 퀘스트 표시                        P0
  EXP-06   **면접 없이도 경험 관리 Markdown 내보내기**    P0
  EXP-07   경험 + 선택 면접 기록 통합 Markdown 내보내기   P0
  EXP-08   역량·프로젝트·키워드 필터                      P1

## 프로젝트 필드

-   필수: 프로젝트명.
-   선택: 유형(실무/팀/개인/교육/기타), 기간, 목표, 개요, 담당 역할,
    성과.

## 경험 카드 필드

  필드          질문                                      필수
  ------------- ----------------------------------------- ------
  제목          어떤 경험인가요?                          예
  프로젝트 ID   어느 프로젝트에서 발생했나요?             예
  상황          어떤 상황이었나요?                        권장
  문제/목표     무엇을 해결해야 했나요?                   권장
  본인 행동     직접 무엇을 했나요?                       권장
  판단 근거     왜 그 방법을 선택했나요?                  선택
  결과/근거     어떤 결과가 있었고 무엇으로 확인하나요?   선택
  배운 점       무엇을 배웠나요?                          선택
  역량 태그     어떤 역량을 보여주나요?                   선택

**실제 사실만 기록.** AI는 경험·성과를 창작하지 않는다.

## 카드 상세 UI

상단: 제목/프로젝트/기록 상태/버전. 본문: 상황·문제·행동·판단
근거·결과·회고. 하단: 역량 태그, 질문별 활용 답변, 회사별 활용 이력,
경험 강화·전달 강화 퀘스트.

## 상태 규칙

-   `draft`: 제목+프로젝트만 존재할 수 있음.
-   `ready`: 핵심 필드가 작성됨(구체적인 충족 기준은 구현 설정).
-   `needs_review`: 사용자 또는 평가 결과에서 보완 과제 발견. 상태는
    질문별 답변 점수와 독립.

## 수정과 버전

-   수정 저장 시 `experience_version` 증가.
-   이전 버전은 과거 평가의 참조를 위해 보존.
-   면접 질문 · 답변 진행 중에는 경험 카드를 조회 · 비교 · 선택 · 참고만 하며 생성 · 수정하지 않는다 (PRD 5.3). v2.2 의 '면접 사이드 패널에서 같은 CRUD 동작 제공'은 PRD 와 충돌해 삭제했다. 생성 · 수정은 경험 관리의 [경험 상세 편집]에서 한다.
-   이미 완료된 평가는 수정된 경험으로 재계산하지 않음.

## Markdown 내보내기

### 경험만 내보내기 (`EXPOR-01`)

프로젝트·경험 선택 → 미리보기 → UTF-8 `.md` 다운로드. 면접 기록이 없어도
활성화. 포함: 문서 생성 시각, 프로젝트, 경험 카드 ID/버전/상태, 카드
내용, 역량 태그, 선택한 경우 관련 퀘스트 요약. 미포함: 면접
질문·답변·평가(이 모드에서는 절대 포함하지 않음).

### 통합 내보내기 (`EXPOR-02`)

경험 + 면접 데이터 함께 포함. 상세 형식 `technical/DATA_MODEL.md` 참조.
범위 선택 · 진행 중 면접 포함 여부는 선택 저장 UX와 함께 미확정이다 (PRD 5.6).

## 예외

-   프로젝트 삭제 시 연결 경험 처리 확인(연쇄 삭제 방지).
-   면접에 사용된 경험 삭제는 이력 보존을 위해 소프트 삭제 권장.
-   경험 정보가 부족하면 추천에 '정보 부족' 표시.
-   내보내기 대상 0건이면 다운로드 대신 안내.

## 완료 기준

-   하나의 프로젝트에 경험 2개 이상 생성 가능.
-   면접을 한 번도 하지 않은 사용자가 경험 카드만 `.md`로 다운로드 가능.
-   경험 카드 수정 후 버전이 증가하고 이전 평가가 바뀌지 않음.
-   면접 중에는 경험 카드를 조회 · 비교 · 선택 · 참고만 할 수 있고, 작성 중인 답변이 유지됨.

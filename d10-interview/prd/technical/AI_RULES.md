# 경험 추천 규칙 · AI 평가 명세

> 기준: PRD v2.3 (0장 · 5.1 · 8.2 · 8.4).  
> 1장 · 2부(1차 MVP)는 확정 정책이다. 3부의 경험 추천 · 퀘스트 · AI 초안 규칙은 **[2차 MVP]** 다.  
> 이 문서의 규칙은 목표 정책이다. 현재 코드(`d10-interview/prompts.py` · `d10-interview/coach.py`)와의 차이는 [`../MIGRATION.md`](../MIGRATION.md) 를 본다. 프롬프트 문장은 사용자가 작성한다 ([`d10-interview/CLAUDE.md`](../../CLAUDE.md)).

## 1. 원칙

-   AI는 면접관 반응 · 꼬리질문, 답변 분석 · 평가, 답변 개선 코칭에 쓴다.
-   점수 합계 · 평균 · 최고 점수 반영 · 질문 수 · 꼬리질문 횟수는 **코드가 계산 · 강제**한다. AI가 쓴 합계는 쓰지 않는다.
-   AI는 실제 경험이나 성과를 지어내지 않는다. 필요하면 `[확인 필요: ○○]` 로 남긴다.
-   AI 출력은 모두 strict JSON 스키마로 받는다.
-   경험 추천은 **규칙 기반**으로 구현한다. [2차 MVP]
-   경험 적합도와 활용 답변 점수는 별도 지표다. [2차 MVP]

# 1차 MVP 규칙

## 2. 면접관 (`AI-08`)

-   하나의 일관된 면접관 페르소나로 진행한다. 기존 '빠른 피드백' 면접 방식(꼬리질문 뒤 강점 · 보완점 피드백)은 1차 목표 구조에서 제거한다.
-   본 질문당 선택적 꼬리질문은 **최대 1개**다. AI가 더 묻자고 해도 코드가 막고, 그 질문 문장은 보여 주지 않는다.
-   꼬리질문 유형:
    -   **실무 근거 검증(기본):** 답변의 근거 · 구체성 · 본인 역할 · 결과 확인 방법을 확인한다.
    -   **경험 탐색(필요할 때):** 답변에 드러나지 않았지만 질문의 '보는 점'과 관련 있을 수 있는 경험을 묻는다.
-   면접 진행 중에는 답변 개선 코칭 · 칭찬 · 정답 · 평가를 제공하지 않는다. 반응은 다음 진행을 위한 짧은 반응에 그친다.
-   지원자가 쓰지 않은 경험을 사실처럼 말하지 않는다.
-   이해도(0~100)는 참고 지표이며 범위 밖 값은 코드가 자른다.

## 3. AI 답변 평가 (`AI-05`)

-   **평가 대상:** 실제로 제출한 면접 답변(꼬리질문 답변 포함).
-   **입력:** 질문 · 질문의 '보는 점', 회사 · 직군 · 분야 정보, 면접 기록(질문 · 답변 · 꼬리질문). 경험 카드 내용이나 면접 전에 입력한 경험 내용은 **평가 근거로 쓰지 않는다**.
-   **평가 체계(기존 유지):**
    -   평가위원 4명(실무 전문가 · 논리 분석가 · 커뮤니케이션 전문가 · 채용 담당자)의 위원별 평가: 뽑지 말아야 할 이유 · 좋은 점 · 점수(0~10).
    -   판단이 갈린 곳 · 모두 같은 판단.
    -   답변별 기준 점수 4개(구체성 · 직무 연관 · 구조 · 근거·검증, 각 0~5) · 가장 약한 점 · 다듬은 답(답변에 없는 숫자 · 성과는 넣지 않음) · 확인할 사실(최대 2개).
    -   다음 연습에서 고칠 것(최대 3개).
-   평가 근거는 답변 텍스트에 기반하며, 확인되지 않은 결과를 사실로 단정하지 않는다. 점수는 모의 평가이며 채용 합격 예측이 아니다.
-   평가 결과는 당시 질문 · 답변과 연결해 보존하고, 이후 경험 카드 수정이나 새 회차로 다시 계산하지 않는다.
-   평가 결과에는 그 평가에 쓴 **평가 기준 버전(`rubric_version`)** 을 함께 기록한다 (`DATA_MODEL.md` 의 `Evaluation`). 평가 기준이 바뀌어도 과거 평가는 당시 버전 그대로 보존하고 다시 계산하지 않으며, 버전이 다른 평가끼리 비교할 때는 기준이 다르다는 것을 알린다.

> v2.2 원안(미채택 · 기록용): 평가 항목 예시(질문 적합성 · 본인 행동의 구체성 · 판단 근거 · 결과·학습 설명 · 직무 연결)와 출력(항목별 점수 · 근거 · 잘한 점 2개 · 보완점 2개 · 누락 정보 유형 · `rubric_version`)을 제안했으나, '기존 평가위원 4명 · 기준 4개 체계 유지'로 확정되어 채택하지 않았다. `rubric_version` 기록은 유지한다. '누락 정보 유형'은 2차 퀘스트 매핑(14장) 검토 때 참고한다.

**점수 범위와 계산 방식 (기존 명세 · 현재 코드 기준, 사용자 승인 없이 바꾸지 않음)**

| 항목 | 범위 · 계산 | 계산 주체 |
|---|---|---|
| 위원 점수 | 평가위원 4명이 각각 정수 0~10 | AI |
| 위원 평균 | 위원 4명 점수의 평균 (0~10) | 코드 |
| 답변별 기준 점수 | 기준 4개(구체성 · 직무 연관 · 구조 · 근거·검증) 각각 정수 0~5 | AI |
| 답변 점수 | 기준 4개의 합 (0~20) | 코드 |
| 종합 점수 (최초) | 답변 5개 점수의 합 (0~100) | 코드 |
| 종합 점수 (최신) | 재도전한 질문은 같은 회차 · 질문의 최고 점수(최초보다 높을 때만)로 바꿔 넣은 합 | 코드 |
| 모의 결과 판정 | 합격: 최신 종합 90 이상 · 위원 평균 9.0 이상 / 합격 후보: 70 이상 · 7.0 이상 / 그 외 재도전 필요 | 코드 |
| 다듬은 답 표시 | 답변 점수 14 미만인 답만 | 코드 |
| 목록 길이 | 확인할 사실 답변당 최대 2개, 다음에 고칠 것 최대 3개 | 코드 |

## 4. 평가 응답 검증 (`AI-09`)

AI 응답이 아래를 만족하지 않으면 **정상 평가로 처리하지 않는다.**

| 검증 | 실패 예 |
|---|---|
| 스키마 형식 | JSON 파싱 실패, 필수 칸 누락, 타입 불일치 |
| 평가위원 | 4명 중 누락 · 중복 · 모르는 위원 |
| 점수 타입 | 위원 점수 · 답변별 기준 점수가 정수가 아님 (예: `5.0` · `true` · `"5"`). 범위(3장 표) 밖 정수는 실패가 아니라 보정한다 (처리 순서 5) |
| 답변 번호 · 질문 ID | 질문 수(5)와 다른 개수, 1~5 범위 밖(예: 0부터 매김), 중복 · 누락, 질문 ID 불일치 |
| 필수 평가 항목 | 답변별 기준 점수 4개 중 누락 |

처리 순서:

1.  응답 구조 · 평가위원 · 답변 번호 · 필수 평가 항목 · 점수 타입을 위 표대로 검증한다.
2.  검증에 실패하면 **자동으로 1회 다시 요청**한다.
3.  다시 요청한 응답도 실패하면 사용자에게 평가 오류를 안내하고, 사용자가 평가를 다시 시도할 수 있게 한다. 답변은 그대로 보존한다.
4.  검증에 실패한 결과는 정상 평가로 저장하지 않는다.
5.  검증을 통과한 응답은 범위(위원 0~10 · 기준 0~5)를 벗어난 정수 점수만 경계값으로 보정하고, 보정한 점수로 합계 · 평균을 계산해 저장한다. 원본 응답은 바꾸지 않고, 보정은 정상 처리로 본다.

금지:

-   누락된 점수 · 평가 항목을 만들어 넣지 않는다. 타입이 틀린 점수(`5.0` · `true` · `"5"`)를 정수로 바꿔 쓰지 않는다.
-   누락된 평가위원 점수를 0점으로 채우지 않는다.
-   질문 번호 · ID가 맞지 않는 평가를 순서로 추측해 다른 질문에 연결하지 않는다.
-   평가 실패를 정상 평가로 처리하지 않는다.

원칙:

-   자동 재시도는 오류 복구 수단이며 평가 기준의 문제를 감추는 수단이 아니다. 검증 실패가 반복되면 프롬프트와 평가 기준 자체를 점검한다.
-   기존 평가위원 4명 체계와 3장의 점수 범위는 유지한다.
-   재도전 채점 응답도 같은 원칙(검증 · 범위 밖 정수 점수 보정 · 실패를 정상 평가로 저장하지 않음)으로 다룬다. 재도전 채점에도 자동 재시도 1회를 적용할지는 미확정이다 (PRD 10.2).
-   목록 길이 초과(확인할 사실 3개 이상 등)를 검증 실패로 볼지는 미확정이다. (현재 코드는 앞에서부터 잘라 쓴다.)
-   범위 밖 정수 점수의 경계값 보정은 교육 규칙(`d10-interview/CLAUDE.md` '점수는 범위 밖이면 잘라 쓴다')과 같다. AI 응답 경로는 E-3에서 이 정책을 따른다. 저장 기록 복원 경로는 아직 누락 위원을 0점으로 넣으며 E-5에서 바꾼다 (`../MIGRATION.md`).
-   점수 보정 발생률(평가 품질 분석용)은 후속 검토 항목이다. MVP1에서는 보정을 별도로 기록하지 않는다.

## 5. 재도전 채점 (`AI-10`)

-   다시 쓴 답만 채점한다. 이전 답은 무엇이 바뀌었는지 비교할 때만 본다.
-   최초 평가와 같은 기준(답변별 기준 4개)으로 채점하고, 나아졌다는 이유만으로 점수를 올리지 않는다.
-   재도전 **횟수 제한은 없다.** 재도전마다 새 평가 기록(`attempt_id`)을 남기고 기존 평가를 덮어쓰지 않는다.
-   비교 기준은 같은 회차 · 질문의 재도전 이전 최고 점수이며, 다른 회차의 같은 질문은 참고 정보다 (PRD 8.2).
-   현재 질문 은행에 없는 과거 질문(복원한 기록)도 당시 질문 원문으로 재도전 채점한다. 과거 평가는 다시 계산하지 않는다.
-   AI 비교 코칭은 점수 산출과 분리하며 점수에 영향을 주지 않는다.

## 6. 답변 개선 코칭 · 보조 AI (`AI-11`, 기존 기능)

-   형광펜(답변 문장마다 기준 표시) · 전략 가이드(약한 기준을 올리는 방법)는 면접 완료 후 사용자가 요청할 때만 호출한다.
-   마지막에 할 질문 추천 · 다듬기는 기존 기능이며 1차 유지 여부는 미확정이다 (PRD 10.2).
-   코칭에서도 답변에 없는 경험 · 숫자를 지어내지 않는다.

## 7. 코드가 계산하는 것 (`AI-12`)

-   답변 점수(기준 4개 합, 0~20) · 종합 점수 · 위원 평균 · 판정.
-   재도전 반영: 같은 회차 · 질문에서 최초 점수보다 높은 최고 점수.
-   '역전의 실마리'(1차 유지): 최신 점수가 가장 낮은 답과 그 답의 가장 약한 기준을 코드가 고른다. '퀘스트(전달 강화)'로 전환할지는 미확정이다.

## 8. 호출 비용 통제 (`AI-07`)

-   추천·비교·D-day 정렬은 AI 호출하지 않음. [2차 MVP]
-   평가 결과 캐싱/저장; 조회 시 재평가 금지.
-   재도전은 새로운 답변에 대해서만 평가한다. 횟수 제한은 두지 않는다.
-   질문당 꼬리질문 최대 1개.
-   AI 오류 시 답변 저장 후 재시도.
-   평가 응답 검증 실패 시 자동 재시도는 1회로 제한한다 (4장).
-   형광펜 · 전략 · 마지막 질문은 사용자가 누를 때만 호출한다.

# 2차 MVP 규칙 (경험 추천 · 퀘스트 · AI 초안)

## 9. 질문 분류 (`AI-01`) [2차 MVP]

질문 데이터: `question_id`, `question_type`, `required_competencies`,
`required_evidence`, `role_tags`. 예: 의견 충돌 질문 → 유형
`conflict_resolution`, 역량 `communication, decision_making`, 필수 근거
`conflict, action, resolution`. (`question_id` 는 1차의 영구 질문 ID `Q0001` 을 쓴다.)

## 10. 경험 카드 필터링 (`AI-02`) [2차 MVP]

경험 데이터: `competencies`, `experience_types`, `situation`, `action`,
`reasoning`, `result`, `status`. - 질문 유형·역량 태그로 후보 필터링. -
정보가 적은 경험도 후보에서 제거하지 않고 '정보 부족'으로 표시. -
사용자가 전체 목록에서 후보 2개 직접 선택 가능.

## 11. 적합도 산정 (`AI-03`) [2차 MVP]

초기 예시 규칙(가중치는 테스트 후 확정): - 질문 유형/상황 일치: 50% -
핵심 역량 일치: 30% - 근거 정보 존재 여부: 20%

출력: `높음 / 보통 / 낮음 / 정보 부족` 및 항목별 근거. **정보 충실도는
별도 표시**해 관련성 높은 미완성 경험이 묻히지 않도록 한다. 지원 직무
관련성은 비교 화면에서 별도 강조.

## 12. 추천 이유 (`AI-04`) [2차 MVP]

고정 문구 템플릿: - 유형 일치: '의견 차이와 조율 과정이 기록되어
있어요.' - 역량 일치: '협업과 의사결정 역량을 강조할 수 있어요.' - 근거
부족: '판단 근거가 아직 충분히 기록되지 않았어요.' 추천 근거를 설명할 수
없으면 임의의 이유를 생성하지 않음.

## 13. 선택 경험과 평가 [2차 MVP]

-   답변에 선택 · 참고한 경험의 스냅샷은 **기록용**으로 답변에 연결해 저장한다.
-   선택 경험 스냅샷은 평가 근거로 쓰지 않는다. 평가는 3장(1차)과 같다 (PRD 8.2). v2.2 의 'AI-05 입력: 선택 경험 스냅샷'은 이 원칙에 맞게 기록용으로 바꿨다.

## 14. 퀘스트 매핑 (`AI-06`) [2차 MVP]

퀘스트는 고정 템플릿에서 생성하고 중복 과제는 합친다. 경험 강화 완료는
사실 기록 보완, 전달 강화 완료는 후속 답변에서 기준 충족을 의미.

## 15. AI 경험 카드 초안 생성 [2차 MVP]

생성 원칙은 PRD 5.2 · 8.4 를 따른다 (최초 답변 5개 일괄 분석, 근거 질문 · 답변 연결과 하이라이트, 답변에 없는 경험 · 역할 · 성과 · 수치 생성 금지, 동일 경험 판단이 불확실하면 자동 통합하지 않음). 구현 방식(동일 경험 판별 · 하이라이트 데이터 처리)은 미확정이다 (PRD 10.2).

## 16. 품질 점검

-   동일 입력/루브릭에서 결과가 과도하게 흔들리지 않는가?
-   응답 검증 실패를 정상 평가로 보여 주지 않는가? (1차)
-   면접 중 코칭 · 평가가 나오지 않고, 꼬리질문이 1개를 넘지 않는가? (1차)
-   과거 평가를 새 경험 버전으로 덮어쓰지 않는가?
-   태그는 일치하지만 질문 상황이 다른 경험을 과대 추천하지 않는가? [2차 MVP]
-   높은 적합도이지만 정보가 부족한 경험을 숨기지 않는가? [2차 MVP]
-   참고 여부를 점수 계산에 사용하지 않는가? [2차 MVP]
